# 학습 모델의 사진관 앱 연결

2026-10-18. 앱 파일이 추가된 `2b50203`을 받아 GTX 1660 PC에서 로컬 연결했다.

## 처리 흐름

브라우저 STT의 최종 전사 문장 또는 문장 입력 → 학습 때와 같은 프롬프트 → Llama 3.2 1B + 학습 어댑터 → 함수·인자 허용 목록 검사 → 기존 앱의 설정/촬영 함수.

음성 인식(STT)은 그대로 필요하다. 모델은 STT 뒤에서 기존 키워드 해석기를 대신한다. 앱의 ‘명령 해석’ 선택에서 학습 모델과 기존 키워드를 비교할 수 있다. 학습 모델이 실행 보류나 오류를 반환해도 기존 키워드로 몰래 다시 실행하지 않는다. 화면 버튼은 그대로 동작한다.

## 다른 노트북에서 실행

브랜치에 작은 학습 어댑터와 토크나이저를 포함했다. 원본 모델을 해당 노트북의 승인된 Hugging Face 캐시에 받은 뒤 `python scripts/run_photo_booth.py --trained`로 실행한다. 설치·로그인·카메라 시험은 [다른 노트북 시험 안내](OTHER_LAPTOP_TEST.md)를 참고한다.

## 사용자 지정 경로로 실행

GPU 학습 환경에서 프로젝트 루트를 작업 폴더로 사용한다. `HF_HOME`은 이 PC에서 로그인하고 모델을 내려받은 캐시 경로로 지정한다. 토큰을 명령 인자로 넣지 않는다.

```powershell
python scripts/run_photo_booth.py --model-adapter "학습결과/gpu_full_v09"
```

`--model-adapter`에는 `adapter/`와 `tokenizer/`가 함께 들어 있는 폴더를 지정한다. 모델 파일은 이미 내려받은 로컬 캐시만 읽는다. 준비가 완료되면 `http://127.0.0.1:8770/`에 접속한다. 시작 시 모델을 한 번 로드하고 재사용한다. 모델 옵션을 빼면 기존 키워드 시연으로 실행한다.

현재 PC용 실행 파일은 채팅 산출물의 `start_photo_booth_model.ps1`이다. 이 실행 파일은 현재 PC의 환경과 모델 경로를 사용하며, 다른 PC에서는 경로를 맞춰야 한다.

## API

- `GET /api/photo/config`: 실제 연결된 해석기 확인.
- `POST /api/photo/interpret`, JSON `{"text":"타이머를 삼 초로 설정해 줘"}`: STT 문장 전체를 전달.
- 예시 응답: `{"action":"set_timer","args":{"seconds":3},"raw_output":"<maum_2>(seconds=3)<maum_end>","confirmation_required":false,"latency_ms":1234}`.
- 허용 기능: `select_layout`, `set_frame`, `set_timer`, `capture_photo`, `no_action`, `set_shooting_view`, `adjust_view`.
- `no_action`은 화면 안내만 표시한다. 잘못된 출력은 422, 동시 추론 요청은 503, 추론 오류는 500으로 반환한다. 오류 시 카메라나 설정을 실행하지 않는다.
- 본문은 8KiB, 전사 문장은 512자, 전체 프롬프트는 512토큰 이내로 제한한다. 생성은 최대 32토큰이며 `<maum_end>`에서 멈춘다.
- 루프백 주소에만 바인딩한다. 전사 문장·요청 본문을 서버 로그에 기록하지 않는다.

## 앱 적용 시의 동작

- 설정 결과는 기존 `setSetting`, 구도 결과는 `adjustView`, 촬영은 `capture`에 연결했다.
- 카운트다운 중 중복 촬영 방지, 네 컷에서만 촬영 방법 변경, 배율 1~2배와 위치 한계를 유지한다.
- 추론 중 중복 명령은 실행하지 않는다. 추론 중 사용자가 버튼으로 설정을 바꾸거나 모드를 바꾸면 이전 모델 결과를 적용하지 않는다.
- 실제 검증에서 촬영 화면 명령을 촬영으로 오인한 2건이 있어, 촬영 문장이 불명확할 때는 확인 후 시작한다. “사진 찍어줘”처럼 허용한 명확한 문장은 모델도 촬영으로 해석한 경우 팝업 없이 기존 타이머를 시작한다. 화면의 촬영 버튼은 기존대로 사용한다.
- 서버 시작만으로 촬영이나 마이크 인식을 시작하지 않는다. 기존 앱은 페이지 로딩 때 카메라 연결을 시도하며 브라우저 권한과 장치 상태에 따른다.

## 기록된 성능과 제한

학습 1,280개 전체 1회 완료. 검증 193/256(75.39%), 기본 모델 0/256. 최종 시험 256개는 미평가다. [GPU 결과와 오답 분석](GPU_PC_RESULT.md)에 상세 기록했다.

오답 63개 중 프레임→실행 보류 28, 타이머→실행 보류 16, 배치→실행 보류 10, 배치→촬영 화면 7, 촬영 화면→촬영 2개다. 촬영·구도·실행 보류 항목은 해당 합성 검증에서는 전부 맞았지만, 이것이 실제 음성 환경에서의 정확도를 뜻하지는 않는다. STT 오인식·거리·현장 소음과 실제 카메라 촬영은 별도 점검이 필요하다. 마음AI 최종 코드 및 보드 변환은 이번 연결 범위가 아니다.
