# 연속 발화의 대본 확인 지연 개선

검수일: 2026-10-05 · 브랜치: `codex/presentation-pace-voice`

사용자 기록 `presentation_09d14a93c64b47fd88f3f429198e0a74.json`에서 첫 문장 STT는 발화 종료 후 약 0.35초에 도착했지만 설명 확인은 약 12.81초 뒤에 반영됐다. 첫 모델 요청은 6초 제한을 초과했고, 다음 요청 결과는 새로운 발화가 들어와 요청 버전이 바뀌었다는 이유로 폐기됐다. STT와 모델 판단, 화면 표시의 시간을 구분해 분석했다. 사용자가 추가한 마지막 “감사합니다”는 대본에 포함한다.

## 변경

- 이미 실행 중인 앞 문장 요청의 유효한 결과를 같은 세션·슬라이드 방문에서 항목별로 반영한다. 대기열의 오래된 요청은 계속 건너뛰어 최신 누적 요청이 밀리지 않게 한다.
- 최신 판단·정정·부정·관련된 재설명·미완성 연결·입력 오류가 있으면 오래된 긍정 결과의 반영을 보류한다. 다른 세션, 재방문 전 요청, 종료된 세션, 중복 응답, 변조되거나 형식이 잘못된 근거는 반영하지 않는다.
- 긴 대본의 모델 판단 항목을 최신 발화와 관련된 항목 및 앞선 미확인 앵커로 좁혀 최대 세 개만 요청한다. 앞 문장 문맥과 원래 근거 구간은 보존하며, 유사도는 판단 대상을 고르는 데만 사용한다.
- 모델 항목 ID(`P1` 등)와 발화 근거 번호를 분리한다. 다른 문장을 거의 그대로 인용한 근거, 수치 문장에 숫자가 없는 근거는 미확인으로 처리한다. 실제로 다른 수치를 말한 경우는 판단불가로 처리한다.
- 매 발표 시작 전에 별도 더미 추론으로 모델을 준비한다. 준비 중에는 타이머·마이크를 시작하지 않고 화면 조회는 계속 제공한다. 모델 유지 요청은 30분이다. 준비 실패는 표시하고 재시도할 수 있다.
- 화면은 전사 수신과 내용 확인을 구분한다. 최신 발화 판단 중에도 앞서 확인한 항목을 표시하며, 최신 결과가 필요한 속도·누락 안내는 보류한다.
- 요청·큐 대기·실제 반영 및 확인 항목·이전 요청 결과의 부분 반영을 이벤트에 기록한다. 속도 계산에는 최초 확인 근거의 발화 종료 시각을 사용한다.

## 실제 모델로 기록 재생

설치된 `qwen3:8b`, 요청 제한 6초, `semantic_v16_focused_independent_evidence`로 사용자 기록의 전사를 수정하지 않고 재생했다. 맨 앞 대기 시간만 건너뛰고 이후 전사 도착 간격과 원래 발화 시각을 유지했다. 모델을 메모리에서 내린 상태로 시작해 모델 준비가 발표 시계보다 먼저 완료되는 경로도 확인했다.

최종 측정 수치와 검사 결과는 [검증 JSON](presentation_live_latency_validation.json)에 기록한다. 최종 소스로 재생한 첫 문장 확인은 발화 종료 후 **12.81초에서 1.64초**로 줄어 두 번째 문장 발화 시작 전에 반영됐다. 마지막 “감사합니다”를 포함한 7항목이 설명 확인 상태가 됐고, 8개 모델 요청의 오류는 없었다. 추론 시간은 약 1.29~2.23초였다. 최초 두 비교 실행도 약 1.68초, 1.64초였으며 최종 재생은 코드 SHA-256이 실행 중 바뀌지 않았음을 확인했다. 모델 준비에 걸린 약 4.46초는 발표 시작 전에 완료했다.

| 첫 문장 기록 | 수정 전 | 수정 후 기록 재생 |
|---|---:|---:|
| 발화 종료 시각 | 6.40초 | 원래 시각 유지 |
| 전사 도착 시각 | 6.76초 | 원래 도착 간격 유지 |
| 설명 확인 시각 | 19.21초 | 8.05초 |
| 발화 종료부터 확인까지 | 12.81초 | 1.64초 |
| 두 번째 문장 발화 시작 | 9.08초 | 원래 시각 유지 |

이 시험은 저장된 전사의 로컬 모델 재생이다. 이번 수정으로 실제 마이크를 새로 녹음하거나 STT 정확도·물리적인 발화 종료 시각을 재측정한 것은 아니다. 이 대본 한 번의 결과를 다른 문장·기기·부하의 지연 보장이나 일반적인 의미 판단 정확도로 확대하지 않는다.

재현 명령(프로젝트 루트):

```bash
.venv/bin/python -m unittest discover -s tests -v
node tests/test_presentation_ui.cjs
.venv/bin/python scripts/validate_live_coaching_latency.py --record /절대경로/presentation_09d14a93c64b47fd88f3f429198e0a74.json
```

재생 도구는 음성 출력을 거절하는 대체 객체를 사용한다. 모델 다운로드, 스피커 재생, 마이크 입력, 운영체제 볼륨·음소거 변경은 하지 않는다. 원시 재생 기록은 `logs/live_coaching_latency/`에 저장하고 Git에 포함하지 않는다.

## 최종 확인 및 다음 실제 시험

최종 전체 Python 회귀 **291개**(135.262초), 화면 DOM 검사 **59개**, Python·JavaScript 구문 검사와 Git diff 검사를 통과했다. 세션이 새 발화를 처리하는 동안 앞 문장의 확인이 보이는지, 대기열 중간 요청을 건너뛰는지, 새 정정과 부정이 오래된 확인을 막는지, 모델 준비 실패와 서버 종료가 지연된 발표 시작을 막는지 검증했다. 누락 안내를 보류한 뒤 상태 변경 없는 최신 판단이 완료돼도 다시 검토하는 경로와 STT가 공백을 넣은 부정 표현도 검사했다.

[최종 준비 화면](presentation_live_latency_ready.png)은 마지막 “감사합니다”를 포함한 7구간, 목표 90초, 음성 안내 꺼짐 상태다. 다음 실제 낭독에서 같은 대본을 읽고 첫 문장 확인 시각과 빠름·느림 안내를 확인한다. 실제 마이크·모델 동시 부하, 이어폰 청취와 보드 동작은 별도 시험이 남아 있다.
