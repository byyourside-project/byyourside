## 구현 검토

F1의 원인이었던 부모/자식 예산 불일치는 수정됐다. transcribe와 warm-up의 IPC 메시지에 요청 예산을 포함하고 자식이 이를 적용한다. 자식 TimeoutError도 별도 메시지로 반환하고 부모가 회수 후 TimeoutError를 유지한다. broad TypeError fallback은 제거됐다. 실제 자식에서 짧은 기본값/긴 override, 반대 방향 실패와 동일 부모 재실행을 검증하는 회귀가 추가됐다.

F2의 핵심인 고정값 감산은 신규 테스트에서 실제 perf_counter 이벤트 차이로 대체됐다. warm-up 추론과 spawn을 포함한 전체 호출 시간, 비추론 왕복 오버헤드의 해석도 분리됐다. 테스트 모듈별 수는 실제 discovery 구조와 일치한다.

## 잔여 사항과 처리 범위

아래 사항은 실사용 평가 도구 정비에 포함한다. 별도 Revision 07 구조 재작성은 요구하지 않는다.

1. `t_req_issued`는 송신 **직전**, `failure_caught_ts`는 pipeline 정리 후 예외 전파 **직전** 시각이다. 보고서의 송신 완료/호출자 포착이라는 설명은 정확하지 않다. 실제 호출자 catch 시각과 구분한다. 최초 세그먼트 시각과 마지막 요청 시각의 조합은 다중 요청 실패의 단계 분해에 그대로 일반화할 수 없다.
2. run_id에 revision을 넣어 과거 revision과 분리했지만 같은 revision 재실행에는 여전히 append되고 요약 JSON은 덮어써진다. 실행별 UUID/디렉터리를 추가한다. PM 테스트 재실행 역시 기존 고정 ID 로그에 추가될 수 있어 독립 콘솔 로그를 보존했다.
3. 기존 Rev05 테스트에는 상수 기반 시간 분해와 warm-up 반환값을 restart라고 출력하는 부분이 남아 있다. 최신 지표로 채택하지 않으며 다음 평가 도구 정비에서 정정한다.
4. 개발자 시나리오 요약은 revision 06이지만 git_revision은 `e7e9dc3`다. 커밋 전 변경 상태에서 실행했을 수 있으므로 이 파일만으로 현재 커밋의 무변경 실행을 증명하지 않는다. 다음 실행은 커밋과 dirty 상태 또는 파일 해시를 함께 보존한다. 이번 PM 검수에서는 시나리오 전체를 재실행하지 않았다.
