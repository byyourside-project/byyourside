# 발표 중 후속 구현: 로컬 의미 코칭과 평가
검증일: 2026-10-04. 기본 PhraseCoach를 유지하며 설치된 Ollama 모델을 선택적으로 연결한다.

## 구현
- Ollama chat API 어댑터와 실행 옵션, 설치된 로컬 모델 확인, 별도 더미 준비 호출.
- 핵심 문장과 실제 발화를 전달하고, 항목·근거 번호와 정수 상태 코드의 짧은 JSON을 원래 ID로 복원한다.
- 잘못된 상태·존재하지 않는 근거·불완전 JSON·잘린 생성·컨텍스트 한도·타임아웃은 판단불가로 처리한다. 기존 세션 검증을 함께 적용한다.
- 모델 이름·digest·준비 시간·요청 시간·추론 통계를 세션에 기록한다.
- 정답 전사 평가 CLI가 실패 사례·오확인·오안내·구조 유효성과 요청 지연을 별도로 저장한다.
- HTTP 계약, 출력 검증, 근거 복원, 정답 유출 방지, 오류를 성공으로 세지 않는 평가 테스트를 추가했다.

## 개발 평가 결과
모델: 설치된 qwen3:14b, Q4_K_M. 최종 prompt_version: semantic_v5_integer_arrays.

| 방식 | 맞은 사례 | 구조 유효성 | 요청 p95 |
| --- | --- | --- | --- |
| 기본 문장 매칭 | 14/20 (70%) | 100% | 약 0.07ms |
| 초기 의미 모델 v1 | 18/20 (90%) | 100% | 6710ms |
| 중간 v3, 발화 번호 압축 | 20/20 (100%) | 100% | 977ms |
| 최종 v5, 항목 번호·정수 응답 | 19/20 (95%) | 100% | 1120ms |

최종 상세 결과: [coaching_quality_eval_v5.json](coaching_quality_eval_v5.json).
v3는 이전 방식의 결과이며 최종 정확도 근거로 사용하지 않는다.
사례는 프롬프트 조정에 사용한 동일한 20개이며 독립 평가가 아니다.
보류 사례 2개를 제외한 추론은 20회다. 누락 오안내 0/19, 설명 오확인 0/12.
C16에서 틀린 수치를 올바른 값으로 정정한 발화를 판단불가로 남겼다.
DEVELOPMENT_PASS는 개발 기준(정확도 90% 이상 등) 통과이며 실사용 승인이나 완벽한 의미 판단을 뜻하지 않는다.

## 화면 통합과 제한
예제 첫 슬라이드의 항목 2개를 미등록 바꿔 말하기 한 문장으로 설명했다.
기본 2초 제한에서 최종 v5도 타임아웃이 재현됐고 두 항목이 판단불가가 됐다.
5초 제한에서는 두 항목 모두 발화 manual:1을 근거로 설명됨으로 표시됐다.
서버 판단 처리 시간 2377ms, 모델 HTTP 요청 2377ms였다.
단일 요청이며 다중 항목 p95나 발화 종료부터 화면까지의 시간으로 해석하지 않는다.
[성공 화면](presentation_semantic_preview.jpg), [기본 제한 시간 화면](presentation_semantic_timeout.jpg),
[최종 세션 검증 기록](presentation_semantic_ui_validation.json).

~~~bash
.venv/bin/python scripts/run_presentation.py --ollama-model qwen3:14b --coach-timeout 5 --port 8766
.venv/bin/python scripts/evaluate_coaching.py --ollama-model qwen3:14b --warm-up
~~~

2초 기본값은 유지한다. 긴 슬라이드·발화 누적에서는 더 지연될 수 있다.
준비 호출과 로딩은 따로 기록하며 준비 호출은 개발 사례 p95에서 제외했다.
최종 개발 평가 준비 시간은 약 1초였으며 이미 준비된 환경이었다. 초기 로딩 성능을 뜻하지 않는다.
마이크를 켜거나 모델을 추가 다운로드하지 않았다. 실제 STT+LLM 동시 성능은 미검증이다.
