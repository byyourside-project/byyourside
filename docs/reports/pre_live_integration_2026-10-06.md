## 통합한 동작

`start_by_your_side.cmd`는 발표 전(기본 8765)과 발표 중(기본 8766)을 함께 실행한다. 두 화면에서 서로 이동할 수 있고, 발표 전의 **이 대본으로 발표 준비**에서 대본·목표 시간·제목을 전달한다. 사용자가 자료 교체를 확인해야 하며, 발표 중 화면에서 직접 시작한다. 자료 전달은 마이크·타이머·음성 출력을 시작하지 않는다.

잘못된 입력과 진행 중·모델 준비 중 세션의 자료 교체는 거부한다. 오류가 나면 이전 준비 자료가 보존된다. 이미 열린 발표 중 화면도 준비 자료 변경을 반영한다. 영상 분석 결과나 수정 전사는 학습 정답으로 자동 전달하지 않는다.

Windows에서 Unix 전용 `resource` 모듈을 불러오던 오류를 수정했다. Windows 메모리는 `psutil`의 최대 작업 집합을 우선 사용한다. 기존 발표 전 단독 실행도 유지한다.

## 모델과 판단 범위

- 통합 실행 기본값은 등록 표현을 비교하는 `PhraseCoach`이며 UI에 문장 매칭 모드로 표시한다. 바꿔 말하기와 전사 오타에 한계가 있다.
- 설치된 Ollama 서버와 모델이 있으면 `--ollama-model qwen3:8b`로 팀원의 의미 판정 연결을 사용할 수 있다. 기본 실행은 모델을 다운로드하지 않는다.
- 발표 전은 비교 가능한 발화 구간의 상대 속도와 카메라 방향 추정이다. 실제 청중과의 눈맞춤 판정이 아니다.
- 발표 중은 대본 길이에 비례한 배정 시간과 확인된 발화 완료 시각을 비교한다. 처리 지연을 제외하며 125% 초과는 빠름, 75% 미만은 느림이다. 절대적인 발음의 적정 속도나 전달력 점수가 아니다.
- 화면은 첫 문장 확인부터 표시하고, 처리 중·종료 후에는 마지막 확인 값임을 안내한다.
- 선택적 음성은 기본 꺼짐이며 빠름·느림만 안내한다. 발화 15초·대본 10% 이상, 같은 상태 5초 유지, 같은 방향 최소 30초 간격 등의 조건을 적용한다.
- 음성 출력은 현재 macOS `say`/Yuna 전용이다. Windows와 QCS6490에서 비활성화된다.

## 확인 결과

| 확인 | 결과 | 범위 |
| --- | --- | --- |
| Python 전체 검사 | 404개 통과, 211.217초 | 발표 전·중 및 기존 음성 처리 회귀 검사 |
| 화면 DOM 검사 | 79개 통과 | 상태 표시와 입력 제어 |
| 신규 통합 검사 | 6개 통과(404개에 포함) | 화면 주소, 자료 전달, 입력 오류, 실행 중 보호, 요청 출처, Windows 메모리 |
| 브라우저 | 대본 전달 → 3구간 직접 전사 입력 → 종료·기록 저장 확인 | 마이크 없이 사용자 흐름 확인 |
| 산출물 | PPT 11장·HWP 8쪽 렌더 확인 | PPT 구조·배치 검사 통과, HWP 재읽기 확인 |

전체 검사는 `python -X utf8 -m unittest discover -s tests -p "test_*.py" -q`로 실행했다. 공식 한국어 예제와 기존 연속 발화 시험 자료를 `scripts/prepare_test_audio.py`로 준비했다. 배포 묶음의 SHA256을 확인하며 개인 녹음을 사용하지 않는다. 음성 안내 상태 검사는 모의 출력을 사용한다. 메모리 검사는 OS별 고정 최소 사용량 가정 대신 부모·자식 프로세스 분리와 합계를 확인한다.

브라우저 시험의 219% 등 화면 수치는 직접 입력 시각에서 계산한 기능 확인 결과다. 실제 마이크 발음 속도나 의미 모델 정확도 측정값이 아니다. 원본 검사 로그·시험 세션·렌더 파일은 Git에서 제외된 `logs/`에 보관한다. HWP는 별도 렌더러로 확인했으며 한컴 프로그램의 동일 렌더링을 보증하는 검사는 하지 않았다.
