# 목표 발표 시간 대비 빠름·느림 음성 안내

구현·검수일: 2026-10-05
작업 브랜치: `codex/presentation-pace-voice` · 시작 커밋: `53cce34`

## 동작

대본과 목표 발표 시간을 입력하면 대본의 공백·문장부호 제외 글자량에 비례해 시간 계획을 만든다. 확인된 고유 대본량에 해당하는 계획 소요 시간을 실제 발화 종료 시각과 비교해 속도를 판단한다. 발화가 끝난 뒤 STT·모델 결과를 기다린 시간은 계산에서 제외한다. 반복해서 읽은 구간은 진행량과 최초 확인 시각을 늘리지 않는다.

발화 종료 시각 15초 이상, 대본 10% 이상 확인된 상태에서 계획 속도의 125% 초과이면 빠름, 75% 미만이면 느림이다. 경계와 그 사이는 계획 내다. 같은 방향이 5초 유지된 뒤 짧게 안내하며 같은 방향의 반복 안내는 실제 안내 발생 시각부터 최소 30초 간격이다. 정상적인 모델 대기는 방향 후보를 유지하지만 결과가 나오기 전에는 화면·음성을 보류한다. 새 발화, 방향 변화, 불확실한 전사·누락·품질 문제·오래된 근거·종료는 유효하지 않은 안내를 철회한다.

안내 문구:

- 빠름: “계획보다 빠릅니다. 조금 천천히 말씀해 주세요.”
- 느림: “계획보다 느립니다. 조금 더 빠르게 이어가 주세요.”
- 계획 내 또는 근거 부족: 속도 음성 안내 없음.

음성 안내는 사용자가 켜며, 기본 범위는 **빠름·느림만**이다. 이 범위에서는 잔여 시간·초과 시간·내용 누락·종료 리뷰를 음성으로 읽지 않는다. 화면 알림은 유지한다. **전체 안내**를 선택하면 기존 알림도 음성 대상이 된다. 사용자가 누른 음성 시험 버튼은 진행 중이며 음성이 켜진 상태에서만 허용한다.

음성 끄기·범위 변경 시 세대 번호로 옛 큐 항목을 무효화한다. 껐다가 다시 켜도 옛 항목이 되살아나지 않는다. 종료 후에는 음성을 새로 시작하지 않고 실행 중인 출력도 취소한다. 큐 수락·시작·완료 이벤트의 순서를 보장하고 종료·예외 경로에서 자식 프로세스를 회수한다. 큐 포화와 출력 불가·종료 상태의 요청은 거절·기록한다.

화면은 목표 시간, 확인된 발화 종료, 기준·현재 확인 속도, 계획 대비 비율, 예상 전체 시간, 보류 이유와 처리 지연을 표시한다. 실제 발음 속도나 모든 상황에서의 완주 시간 예측을 보장하는 기능은 아니다.

## 조용한 검증

이번 작업은 사용자가 스피커를 끄고 취침할 예정이라는 조건에 맞춰 **소리 재생 없이 검증**한다. macOS의 볼륨·음소거·출력 장치 설정을 변경하지 않는다. 회귀 테스트의 음성 출력은 가짜 프로세스로 대체한다. 실제 음성 합성 검증은 모든 `say` 호출에 `-o`를 추가해 WAV 파일로만 저장한다. 파일의 프레임 수·샘플레이트·신호와 큐·시작·완료 기록을 확인하며 `afplay`나 출력 장치 재생은 호출하지 않는다.

재현 명령(프로젝트 루트):

```bash
.venv/bin/python -m unittest discover -s tests -v
node tests/test_presentation_ui.cjs
.venv/bin/python scripts/validate_pace_voice.py
```

마지막 검증은 로컬 SenseVoice 예제 WAV와 설치된 8B 모델을 사용한다. 빠름·느림·계획 내 조건의 발표 시각은 통제한 테스트 입력이다. 실제 사람의 발음 속도, 실제 마이크 캡처, 이어폰 청취를 검증한 것으로 표시하지 않는다. 합성 음성 파일과 원시 로그는 `logs/pace_voice_validation/`에 저장하고 Git에는 넣지 않는다.

최종 수치·검증 근거는 [검증 JSON](presentation_pace_voice_validation.json)에 기록한다.

최종 전체 Python 회귀 **245개**(134.697초), 화면 DOM 검사 **42개**, 구문·diff 검사 모두 통과했다. 대본 미확인 보완에는 신규 10개를 포함한 22개 검사가 있다. 실제 SenseVoice 전사와 설치된 `qwen3:8b`로 빠름·느림·계획 내 조건을 확인했고, 빠름·느림 각각 22,050Hz·약 3.5초의 WAV 파일을 합성했다. 계획 내 조건에는 음성 파일이 생성되지 않았다. 예제 첫 세 문장(숫자 포함)의 실제 모델 텍스트 처리도 확인했다. 검증 JSON은 최종 소스·검사 파일의 SHA-256을 기록한다.

브라우저에서는 직접 전사 모드와 실제 시계·로컬 모델로 예제 첫 두 문장의 확인, 계획 내/빠름 표시 및 오래된 발화 근거의 보류를 확인했다. 음성 체크박스는 계속 꺼 두었다. [보류 화면](presentation_pace_voice_waiting.png)은 근거가 15초보다 오래된 상태이며, 지난 속도 수치를 숨기고 보류 이유를 표시한다. 검수 후 발표를 종료하고 예제 목표 시간을 90초로 복원했다. [최종 준비 화면](presentation_pace_voice_ready.png)에 음성 안내 꺼짐과 빠름·느림 범위가 표시된다.

이 검수에서 숫자 문장을 그대로 입력했는데도 모델이 미확인으로 응답하는 사례를 발견했다. 최신 발화 전체가 완성된 대본 문장과 정확히 일치하는 경우에만 이 미확인을 보완한다. 모델이 모순·불확실로 판단한 내용, 미완성 문장, 질문·인용·명령·뒤따른 정정은 자동 확정하지 않는다. 재현 문장은 실제 모델을 연결한 텍스트 검증에 추가했다.

## 다음 실제 확인

이어폰을 출력 장치로 선택하고 음소거를 해제한 뒤, 같은 대본에 서로 다른 목표 시간을 넣어 실제 낭독해 빠름·느림 안내와 취소를 확인한다. 실제 청취와 장시간 동시 부하 및 보드 출력은 별도 시험이 필요하다. 이번 검증을 위해 자동으로 음소거를 해제하지 않는다.
