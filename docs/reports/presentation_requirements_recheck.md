# 발표 중 요구사항 재검토

검토일: 2026-10-05
기준: 사용자 설명과 실제 종료 기록 `presentation_99c453548b794872a6e3de9466ba1fc2.json`.

## 결론

현재 구현은 사용자가 요청한 발표 중 기능을 완성하지 못했다. 슬라이드 핵심 항목 확인·타이머·화면 알림을 구현했으나, 대본 입력과 진행 위치 추적, 대본으로 사전 계산한 속도 기준, 음성 피드백은 없다. 이전 계획에서 속도와 TTS를 후속 확장으로 둔 것은 이번에 확인한 사용자 핵심 요구와 맞지 않는다. 자동 테스트 통과와 일부 항목 확인 성공을 제품 기능 완료로 해석하면 안 된다.

## 새 실제 기록 검토

- 최종 상태는 설명됨 5/6, 판단불가 1/6. 실제 발화 정답이나 원본 음성 없이 이를 정확도 83.3%라고 부를 수 없다.
- 두 번째 슬라이드의 정책 문장이 전사에서 다른 표현으로 인식되어 의미 판단이 판단불가였다. 원래 음성이 맞았는지 이 JSON만으로 확인할 수 없다.
- 마지막 슬라이드 첫 문장은 음성 시작 34.08초, 수동 전환 34.35초로 전환 경계에 걸렸다. 두 슬라이드에 연결되어 내용 판단을 보류했다. 대본 위치로 대상 내용을 찾는 기능이 없으므로 버튼 전환 시각에 크게 의존한다.
- 22ms의 빈 전사까지 내용 품질 판단 경로로 들어갔다. 잡음성 짧은 꼬리와 실제 불확실 발화를 구분할 필요가 있다.
- 모델 요청 한 번은 약 8.02초에 타임아웃. 이미 새 요청으로 대체된 결과여서 세션 오류 목록에는 없지만 이벤트에는 남았다. 성공 요청도 처음 항목의 기록상 음성 종료부터 판단 이벤트까지 약 12.37초, 다음 항목 약 7.85초였다. 화면 렌더 지연과 사람 기준 발화 종료는 이 파일로 직접 측정하지 못한다.
- 화면 알림 기록은 없고 음성 출력 구현도 없다. 누락·속도 음성 피드백을 받은 시험이 아니다. 시험 중 관련 시간 조건이 발생했는지도 구분해야 한다.

## 사용자가 원하는 핵심 흐름

1. 발표 전에 대본과 총 목표 시간을 입력한다. 슬라이드별 대본/시간은 가능하면 함께 받는다. 대본을 순서가 있는 문장·내용 단위로 나누고 필수 설명 항목을 준비한다.
2. 대본 길이와 목표 시간으로 기준 진행 속도와 예정 구간 시간을 계산한다. 리허설 기록이 있으면 개인 기준으로 보정한다. 사용자는 발표 시작 전에 기준을 확인한다.
3. 발표 중 STT 결과를 대본의 현재 위치 및 주변 구간과 맞춘다. 바꿔 말하기를 허용하되, 부정·수치 변경·정정·전사 불확실성을 구분한다. 대본을 문자 그대로 읽었는지와 핵심 의미를 전달했는지는 따로 다룬다.
4. 뒤쪽 내용까지 진행한 근거가 있을 때 앞에서 건너뛴 필수 내용을 누락 후보로 확인한다. 아직 설명할 차례가 아닌 항목을 누락이라고 알리지 않는다. 위치를 못 찾으면 확인 필요로 둔다.
5. 현재 대본 진행량과 실제 경과 시간을 예정 진행량과 비교해 빠름/느림과 종료 예상 시간을 계산한다. 짧은 멈춤·오인식·반복 낭독에 과민하게 반응하지 않는다.
6. 필요한 안내를 음성으로 출력한다. 예: “앞의 비용 설명을 확인해 주세요”, “계획보다 빠릅니다. 조금 천천히 말씀해 주세요.” 화면에도 같은 내용을 남긴다. 정상 진행에서는 불필요한 음성 개입을 억제한다.
7. 발표 후 대본 위치, 미확인/누락 후보, 속도 변화, 실제 음성 안내의 재생/실패/취소 이력을 저장한다.

## 구현 격차와 작업 우선순위

| 순서 | 작업 | 현재 상태 | 완료 기준 |
|---|---|---|---|
| 1 | 대본 입력 및 사전 시간 계획 | 없음 | 텍스트 대본을 직접 넣고 목표 시간·구간별 기준을 시작 전에 확인 |
| 2 | 순서 있는 대본 진행 추적 | 없음 | 반복·바꿔 말하기·4초 분할·수동 슬라이드 경계에서도 위치와 근거 기록 |
| 3 | 건너뛴 필수 내용 확인 | 핵심 항목 전환 점검만 있음 | 다음 구간 진행 근거가 있을 때 누락 후보 안내, 추적 불확실 시 보류 |
| 4 | 사전 기준 대비 속도 판단 | 없음 | 예정/실제 진행량, 추정 종료 시간, 지속적인 빠름/느림을 비교 |
| 5 | 음성 안내 | 없음 | 비동기 음성 큐, 간격·중복·우선순위, 지난 안내 취소, 실제 재생 기록 |
| 6 | 실제 음성 통합 검증 | 일부 단시간 기록만 있음 | 대본 기반 정상·누락·빠름·느림·정정·침묵 시험 및 음성 출력 확인 |

1~5는 발표 중 핵심 기능이다. Q&A·자동 화자 분리·PPT 자동 추출은 이 핵심 흐름 이후의 별도 기능으로 둔다. 기존 STT·세션·타이머·이벤트 저장·의미 모델·알림 정책은 재사용할 수 있다.

## 데이터와 판단 규칙

- 새 대본 계약은 현재 공통 계약 v1과 구분해 구현·검증할 때 버전을 올린다. 현재 프로그램이 대본을 지원하는 것처럼 v1 예제를 바꾸지 않는다.
- 필요한 필드: 대본 원문, 순서 있는 구간 ID/텍스트, 필수 항목, 목표 시간, 사전 계산 방식 및 기준값, 선택적 슬라이드 연결, 음성 안내 설정.
- 진행 속도와 발음 자체의 속도는 다르다. 대본의 고유 진행량/경과 시간은 계획 대비 진행 속도이며, 중복 발화는 진행량을 늘리지 않는다. 최근 전사 길이/음성 구간 시간은 근사 말하기 속도로 별도 표시한다. 음절·어절 등 단위와 무음 포함 여부를 명시한다.
- 예를 들어 선택한 길이 단위 2,400개를 목표 5분에 전달하려면 기준은 분당 480개다. 이는 해당 대본의 계획값이지 모든 발표에 적용하는 적정 속도가 아니다. 숫자·약어 낭독 및 멈춤의 차이는 리허설로 보정한다.
- 대본 위치를 못 찾거나 음성 손실이 있으면 “느림”이나 “누락”으로 단정하지 않는다. 충분한 구간과 지속 시간, 추적 신뢰도 조건을 정해 시험한다.
- TTS는 UI·STT를 막지 않아야 한다. 발표자가 듣는 이어폰 출력을 우선 평가한다. 스피커 사용 시 안내 음성이 마이크로 재입력되는 문제를 검증하고 마이크를 끄는 방식으로 발화 손실을 숨기지 않는다.
- LLM은 내용 대응과 불일치 판단에 사용하고 시간·속도 계산은 규칙과 시계로 처리한다. 현재 맥의 qwen3:14b 성능은 보드 성능의 증거가 아니다.

## 완료 판단

대본을 먼저 넣고 정상 설명, 중간 내용 건너뛰기, 같은 내용을 빠르게/느리게 말하기를 각각 시험한다. 실제 음성 안내가 들리고 대응 근거와 재생 이력이 저장돼야 핵심 기능 완료로 판단한다. 지금 상태는 이 기준에 미달한다.
