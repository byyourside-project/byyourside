# 대본 기반 발표 중 기능 구현·검수

작성일: 2026-10-05. 기존 범위 재검토 이후 핵심 기능을 구현했다.

## 구현 결과

- 텍스트 대본 입력, 문장/줄 단위 분할, 총 목표 시간에서 길이 비례 구간별 예정 시간과 기준 진행 속도 계산.
- 순서 있는 대본 구간과 STT/직접 전사 연결. 확인 위치·다음 내용·고유 설명량 기록. 반복 설명은 진행량을 증가시키지 않는다.
- 주변 구간과 전사 유사도로 선택한 후보를 의미 모델에 전달한다. 유사도는 후보 탐색용이며 설명됨 승인은 모델 판단/근거 검증을 거친다.
- 두 개의 뒤쪽 설명 또는 마지막 구간 설명을 확인했을 때 앞의 미확인 구간을 건너뛴 후보로 안내한다. 늦게 설명하면 철회한다. 불확실한 항목을 확정 누락이라고 하지 않는다.
- 최소 15초·10% 대본 확인·5초 지속·계획 대비 ±25% 조건으로 진행 빠름/느림을 안내한다. 최근 15초 내 근거, 처리 대기 없음, 지나온 미해결 구간 없음이 필요하다. 시간 계산은 LLM 밖에서 수행한다.
- macOS 설치된 Yuna 음성을 `say`로 비동기 재생한다. 기본 꺼짐, 시작 전/진행 중 켜기·끄기, 안내 음성 시험 버튼. 우선순위 큐 8개, 만료/변경된 안내 취소, 출력 프로세스 종료 및 실패 기록.
- 대본 원문·계산된 시간 계획·위치·누락·속도 상태·음성 재생 이벤트를 세션 schema_version 2에 저장한다. 기존 슬라이드 모드는 schema_version 1을 유지한다.
- 기존 실제 마이크 검수에서 발견한 무음 이후 잔여 음성 전달, 분할 문장 판단 보류 해제, 빈 전사로 상태를 훼손하지 않도록 보완한 변경도 포함한다.

## 사용과 한계

실행/시험 절차는 `docs/user/presentation_script_guide.md`. 기본 예제는 `examples/presentation_script.txt`와 `examples/presentation_script_deck.json`이다. 실행 시 기본 자료도 대본 예제로 변경했다.

현재 대본은 단일 연속 흐름으로 추적한다. PPT/PDF 파싱·페이지 자동 동기화, 리허설 자동 보정, 실제 발음 음절 속도 판정은 포함하지 않는다. 모든 대본 구간을 필수로 취급한다. 최대 50구간/20,000자이며, 구간별 1,000자 제한이다.

macOS TTS를 구현했으며 QCS6490/Android의 TTS 실행을 의미하지 않는다. 보드 전원 수리 후 보드 런타임과 출력 장치를 별도로 검증해야 한다. 새 버전의 사람 마이크·이어폰 동시 발표 시험, 스피커 재유입, 600초 동시 부하 및 독립 대본 정확도·실제 발화 종료 라벨의 지연 측정은 남아 있다. 이번 브라우저 시험은 직접 전사를 사용했다.
