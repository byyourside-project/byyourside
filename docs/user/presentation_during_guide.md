# 발표 중 기능 실행 안내

작성일: 2026-10-04

## 실행

프로젝트 루트에서 실행한다. 새 패키지 설치 없이 Python 표준 라이브러리로 로컬 서버를 구동한다. 마이크 모드는 기존 프로젝트 가상환경의 STT 의존성과 모델 파일이 필요하다.

```bash
.venv/bin/python scripts/run_presentation.py
```

브라우저에서 `http://127.0.0.1:8765`를 연다. 포트가 사용 중이면 `--port 8766`처럼 다른 포트를 지정한다. 서버는 루프백에만 바인딩한다.

## 화면 사용

1. 기본 예제 자료를 사용하거나, **발표 자료 불러오기**에서 공통 스키마의 JSON 파일을 선택한다.
2. 입력 방식에서 **직접 전사 입력** 또는 **마이크**를 선택한다.
3. **발표 시작**을 누른다. 마이크 입력은 이때부터 모델을 준비하고 시작한다.
4. 현재 슬라이드, 전체·슬라이드 타이머, 핵심 항목 상태와 최근 발화를 확인한다.
5. **이전/다음** 또는 왼쪽 슬라이드 버튼으로 전환한다.
6. **발표 종료**를 누르면 음성 입력을 멈추고 마지막 발화·판단을 처리한 뒤 결과를 저장한다.
7. **기록 저장**으로 현재 기록을 JSON으로 내려받을 수 있다. 진행 중 내보낸 파일은 중간 결과다.

직접 전사 입력은 마이크 없이 기능을 확인하는 방법이다. **4초 분할 · 이어 말하기**로 조각을 전달하면 판단을 보류하고, 다음 **문장 종료** 발화와 함께 평가한다. 전사 입력 시간은 기본적으로 전달 시점 직전 최대 4초이며 실제 음성 측정값이 아니다.

## 구현된 동작

- 시작·종료, 수동 슬라이드 전환, monotonic clock 기반 타이머.
- 기존 STT의 확정 전사 이벤트 연결과 입력 오류·손실 기록.
- 슬라이드 방문별 문맥 유지, 분할 발화의 후속 연결, 전환 경계 발화의 판단 보류.
- 핵심 항목별 미확인·설명됨·판단불가 및 근거 구간 기록.
- 전체 잔여 시간·초과 시간과 슬라이드 목표 시간 초과 알림.
- 전환·종료 시 필수 항목의 설명 확인 안내. 미확인을 확정 누락으로 표현하지 않는다.
- 중복 알림 억제, 기본 5초 간격, 우선순위, 기본 10초 표시 기한, 이전 요청의 결과 검증.
- 약 200ms 간격의 화면 상태 조회와 약 1초 간격의 세션 자동 저장.

시간 알림은 전체 시간의 마지막 20%(최대 60초), 전체 시간 초과, 슬라이드 목표 시간 초과를 기준으로 한다. 높은 우선순위의 알림은 낮은 우선순위의 알림보다 먼저 표시된다.

## 내용 판단 방식과 한계

기본 `PhraseCoach`는 **핵심 문장과 사전 등록한 허용 표현을 확인하는 보수적 기준선**이다. 띄어쓰기·문장부호 차이를 정규화하고 허용 표현으로 바꿔 말하기를 지원한다. 가까운 부정·정정이나 동일 문장 구조의 숫자 차이는 판단불가로 남긴다.

등록되지 않은 일반적인 바꿔 말하기는 기본 방식으로 판단하지 않는다. 선택적으로 설치된 Ollama 모델을 연결할 수 있다. 기본 방식의 문장 매칭 성공은 의미 판단 정확도를 입증하지 않으며, 부정·수치 처리는 휴리스틱이다. 따라서 충분한 의미 평가 전에는 알림을 확인 요청으로 사용한다.

### 설치된 Ollama 모델 직접 연결

```bash
.venv/bin/python scripts/run_presentation.py --ollama-model qwen3:14b --port 8766
```

로컬 Ollama 서버가 실행 중이고 지정한 모델이 이미 설치돼 있어야 한다. 자동 다운로드나 클라우드 모델을 사용하지 않는다. 실행 시 더미 발화로 모델을 먼저 준비하고 준비 시간을 별도로 표시한다. 이 시간은 발표 타이머에 포함하지 않는다.

의미 판단 결과는 기존 상태·발화 근거 계약으로 변환한다. 모델 내부에서는 출력 토큰을 줄이기 위해 상태 코드와 발화 번호를 사용하고, 항목 ID도 짧은 번호로 바꾸고 프로그램이 원래 항목·구간 ID로 복원·검증한다. 의미 모델 입력에는 핵심 문장만 보내며 허용 표현 목록은 기본 문장 매칭에서 사용한다. 표시되는 판단 사유는 상태별 일반 설명이며 모델이 생성한 구체적인 사실 인용문이 아니다.

모델 요청 제한 시간 기본값은 2초다. 복잡하거나 긴 슬라이드에서 제한 시간을 늘리려면 `--coach-timeout 5`처럼 지정할 수 있지만, 전체 피드백 지연도 함께 늘어난다. 현재 개발 환경에서는 예제의 핵심 항목 2개를 함께 평가할 때도 2초 타임아웃이 재현됐다. 다중 항목의 실시간 성능은 아직 통과하지 못했으며, 의미 모델 기능 확인에는 5초 제한을 사용할 수 있다. 타임아웃·잘못된 응답·4096토큰 컨텍스트 한도 감지는 판단불가와 품질 문제로 기록한다.

### 정답 전사로 코칭 품질 평가

```bash
.venv/bin/python scripts/evaluate_coaching.py
.venv/bin/python scripts/evaluate_coaching.py --ollama-model qwen3:14b --timeout 60 --warm-up
```

첫 명령은 기본 문장 매칭, 두 번째는 로컬 의미 모델 평가다. 60초는 정확도 측정용 요청 제한이며 실시간 실행 기본값 2초와 다르다. 평가의 지연 판정 예산은 여전히 2초다. `--warm-up`의 더미 호출은 별도 기록하고 사례별 지연에서 제외한다.

개발용 20개 사례는 `examples/coaching_eval.json`에 있으며 정답 상태·누락 후보 여부를 모델 입력에서 제외한다. 오류로 판단불가가 된 항목은 정답이 판단불가여도 성공으로 계산하지 않는다. JSON은 실행별 고유 파일로 저장하고, `--output`으로 이미 존재하는 경로를 지정하면 덮어쓰지 않는다.

`DEVELOPMENT_PASS`는 개발 사례의 정확도·응답 유효성·오확인·오안내·요청 지연 기준을 통과했다는 뜻이다. 실사용·독립 평가·음성 종료부터 화면까지의 성능 통과는 별도다. `CHANGES_REQUIRED`는 exit 2로 반환한다.

사용한 공식 API 계약: [Ollama chat API](https://docs.ollama.com/api/chat), [Structured outputs](https://docs.ollama.com/capabilities/structured-outputs).

로컬 모델을 연결할 경우:

```bash
.venv/bin/python scripts/run_presentation.py --coach-url http://127.0.0.1:9000/coach
```

이 주소는 아래 계약을 구현하는 **별도의 로컬 모델 어댑터 서버**여야 한다. Ollama를 직접 연결할 때는 위의 `--ollama-model` 옵션을 사용한다. 모델 다운로드·학습·별도 어댑터 서버 구동은 포함하지 않는다. 로컬 HTTP만 허용하며 프록시·리다이렉트를 사용하지 않는다. 모델 판단은 별도 작업 스레드에서 수행하고 기본 요청 제한 시간은 2초다.

입력은 `{"task":"presentation_keypoint_judgment","input":{...},"instructions":"..."}` JSON이다. `input`에는 세션 ID, 슬라이드 방문 버전, 요청 revision, 슬라이드 핵심 항목, 최근 발화·근거 구간이 포함된다.

응답 예시:

```json
{
  "judgments": [
    {
      "keypoint_id": "intro-local",
      "status": "explained",
      "reason": "기기 안에서 처리한다는 발화가 해당 항목을 설명합니다.",
      "evidence_segment_ids": ["manual:1"]
    }
  ]
}
```

해당 슬라이드의 모든 핵심 항목을 정확히 한 번씩 반환해야 한다. 상태는 `explained`, `uncertain`, `unconfirmed`만 허용한다. 설명됨·판단불가에는 입력에 존재하는 구간 근거가 필요하다. 오류·타임아웃·잘못된 응답은 판단불가와 품질 문제로 기록한다.

## 저장과 팀 연동

- 기본 결과 폴더: `logs/presentation_sessions/`.
- 세션 JSON: 자료 스냅샷, 방문 구간, 모든 전사, 항목 상태, 알림·억제 이력, 품질 문제, 전체 이벤트.
- STT 원시 로그: 기존 `logs/stt_run_presentation_<session_id>.jsonl`.
- 원본 음성 파일은 이 기능에서 별도로 저장하지 않는다.
- 공통 자료·이벤트 계약: `docs/tasks/presentation_contract.md`.

세션이 끝난 뒤 새 발표를 시작할 수 있다. 기존 세션 파일은 session_id별로 분리된다. 서버는 Ctrl+C로 종료한다.

## 검증 범위

자동 테스트는 세션·타이머·알림·발화 연결·모델 응답 검증, HTTP 흐름, 가짜 마이크의 이벤트 전달·정상 종료, 오류 기록을 확인한다. 실제 발표 코칭 정확도, 최신 버전 600초 마이크 시험, 사람 기준 발화 종료부터 화면까지 p95 3초 목표와 보드 성능은 별도 검증 항목이다.

## 검수 이후 다중 항목 평가

다중 항목 개발 데이터는 examples/coaching_multikeypoint_eval.json이다. 기존 평가 명령에 --dataset 경로를 지정해 사용한다.
보고서 schema_version 2에서는 사례별 points에 각 항목의 정답·실제 상태·근거를 저장한다.
accuracy는 모든 항목과 누락 후보가 맞은 사례 비율이고 point_accuracy는 항목 비율이다.
false_missing/false_explained의 eligible_cases 필드는 호환성을 위해 이름을 유지하며 schema_version 2에서는 항목 수를 뜻한다.

최신 v7은 단일 항목 20/20, 다중 항목 8/8 개발 사례를 맞혔다. 다중 항목 요청 p95는 3.10초여서 2초 목표는 미충족이다.
새 요청이 실패하면 이전 설명됨도 판단불가로 전환한다. 과거 확인 기록은 이벤트에 남으며 다음 유효한 판단으로 다시 확인할 수 있다.
상세 검수 결과는 docs/reports/presentation_coaching_review.md에 기록한다.
