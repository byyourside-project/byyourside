# 발표 전·중 통합 사용 안내

기준일: 2026-10-06. `codex/pre-live-integration` 브랜치에서 사용한다.

## 실행과 전달

1. 처음에는 `.venv\Scripts\python.exe -m pip install -r requirements-app.txt`를 실행한다. 음성·얼굴 모델 설치는 README의 기존 준비 절차를 따른다.
2. 기존 서버 창을 Ctrl+C로 종료한 뒤 `start_by_your_side.cmd`를 두 번 누른다. 발표 전은 8765, 발표 중은 8766 포트를 사용한다.
3. 발표 전 화면에서 영상과 대본을 등록하고 결과의 시간 버튼으로 연습 구간을 확인한다.
4. 실제 발표에 사용할 대본과 목표 시간(초)을 입력한다. **이 대본으로 발표 준비**를 눌러 교체를 확인한다. 영상 분석을 먼저 마치지 않아도 대본을 전달할 수 있다.
5. **발표 중 화면 열기**를 누른다. 전달한 대본과 목표 시간이 맞는지 확인한다. 기존에 열려 있던 발표 중 화면도 새 자료를 반영한다.
6. 기능 확인은 **직접 전사 입력**, 실제 발표는 **마이크**를 선택한다. 마이크는 장치를 고르고 입력 확인 후 **발표 시작**을 누른다. 대본 전달만으로 마이크·타이머·음성이 시작되지는 않는다.
7. 끝나면 **발표 종료**, **기록 저장**을 누른다. 서버 창의 Ctrl+C는 두 서버를 함께 종료한다.

발표 중 자료는 최대 50개 문장/줄, 한 구간 1,000자까지다. 전달 시 제한에 맞지 않으면 원인을 표시하고 기존 준비 자료를 유지한다. 발표가 진행 중이거나 모델을 준비하는 동안은 교체를 거부한다. 영상 분석 결과·시선 수치·교정 전사는 자동으로 발표 중 정답이나 학습 데이터로 전달하지 않는다. 사용자가 입력한 대본·목표 시간·제목만 준비 자료로 보낸다.

## 모델과 음성 안내

통합 실행 기본값은 등록 표현을 비교하는 `PhraseCoach`다. 대본을 그대로 읽는 기능 확인에 적합하며 바꿔 말하기와 STT 오타를 놓칠 수 있다. 화면에도 문장 매칭 모드라는 안내가 나온다. 설치된 Ollama 서버와 `qwen3:8b`가 있으면 아래와 같이 사용한다.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run_by_your_side.py --ollama-model qwen3:8b --open
```

별도 포트는 `--review-port 8875 --live-port 8876`으로 지정한다. 이 경우에도 화면 이동 링크는 실제 포트에 맞춰 생성된다. 기존 `scripts/run_presentation.py`는 팀원 단독 실행 방식과 기본 모델 설정을 유지한다.

음성 안내는 현재 macOS의 설치된 `say`/Yuna 음성만 지원한다. Windows와 QCS6490에서는 해당 기능이 비활성화된다. 음성 기본값은 꺼짐, 켤 때 기본 범위는 빠름·느림만이다. 이 통합 작업에서는 실제 마이크 녹음·스피커 재생·OS 볼륨 변경을 수행하지 않았다.

## 속도 수치 해석

발표 전의 구간 상대 속도와 발표 중의 계획 대비 진행 속도는 기준이 다르다. 발표 중에는 전체 목표 시간을 공백·문장부호를 뺀 대본 길이에 비례해 나누고, 확인한 문장의 배정 시간을 실제 발화 시각과 비교한다. STT·모델 처리 지연은 제외한다. 계획의 125% 초과는 빠름, 75% 미만은 느림이다. 이는 발음의 절대적인 적정 속도 판정이 아니다.

화면은 첫 문장을 확인하면 값을 표시하며 처리 중에는 마지막 확인 값임을 알린다. 음성 안내는 발화 15초·대본 10% 이상, 같은 상태 5초 유지 조건을 적용하고 같은 방향은 최소 30초 간격을 둔다. 자료가 불확실하거나 건너뛴 구간·입력 오류가 있으면 판단을 보류한다.

## 보관과 남은 개발

- 발표 전 자료: `recordings/reviews/` 및 SQLite 목록.
- 발표 중 세션: `logs/presentation_sessions/` JSON. 원본 음성은 별도 보관하지 않는다.
- 두 기록은 저장 형식이 달라 하나의 이력 목록으로 자동 합치지 않는다.
- 발표 후에는 발표 중 화면 상단 **발표 후 리뷰 · Q&A**에서 종료한 기록을 연다. 시간·설명 근거·질문 녹음과 전사 확인·자료 원문 검색·질문 저장·리뷰 내려받기를 지원한다. [사용 안내](presentation_after.md)를 참고한다.
- 마음AI 실제 SDK와 답변 생성 연결, QCS6490 모델 변환과 보드 실행, 실제 시선 정확도와 마이크 동시 부하, Windows·보드 음성 출력은 후속 작업이다.
- 양자화는 팀 수행 범위에서 제외한다.

## 개발 검사

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/prepare_test_audio.py
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p "test_*.py" -q
node tests/test_presentation_ui.cjs
```

첫 명령은 공식 배포 묶음의 체크섬을 확인해 한국어 예제와 기존 연속 발화 시험 파일을 준비한다. Git에서 제외된 개인 녹음을 사용하지 않는다. `-X utf8`은 Windows에서도 한국어 검사 자료를 같은 인코딩으로 읽기 위한 옵션이다.
