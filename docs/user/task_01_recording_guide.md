# Task 01 — 사용자 음성 녹음 및 실사용 평가 가이드

본 문서는 **Task 01 (한국어 음성인식 파이프라인 PoC)**의 최종 실사용 성능을 검증하기 위해 사용자가 직접 수행하는 **30문장 발표 데이터셋 녹음** 및 **10분 연속 발표 마이크 평가** 가이드입니다.

---

## 1. 개요 및 평가 기준

### 1.1 평가 목표
1. **한국어 발표 음성 인식 정확도**:
   - **주 지표 (Primary Metric)**: **공백/문장부호 제거 Corpus CER $\le$ 15.0%**
     $$\text{Corpus CER} = \frac{\sum \text{Levenshtein Distance}}{\sum \text{Reference Characters}}$$
   - **보조 지표**: 공백 포함 CER, 카테고리별(일반, 숫자/단위, 전문용어/영문, 급변구간) CER, Direct STT 대비 VAD 구간 절단 영향 분석.
2. **10분 마이크 연속 발화 안정성**:
   - **무손실 스트리밍**: 오버런(Overrun) 0건, 청크 누락(Chunk Drop) 0건, 세그먼트 누락 0건.
   - **실시간성 (RTF)**: p95 RTF $\le$ 0.5 (오디오 1초당 추론 시간 0.5초 이하).
   - **큐 지연 안정성**: 큐 적체(Runaway Queue Drift) 없음 (드리프트 $\le$ 200ms).
   - **연속 발화 분포**: 10분 중 최소 5개 이상의 분(minute)에 걸쳐 실제 발표 발화가 분포해야 함 (무음 방치 불가).
3. **발화 종료 후 인식 지연**:
   - VAD 감지 종료 기준 지연 p95 $\le$ 1.5초 (사람 청취 기준 정답 라벨링 병행).

## 4. 실제 녹음 방법 및 절차

### 4.1 녹음 준비 (폴더 생성)
터미널에서 녹음 대상 디렉터리를 생성합니다:
```bash
mkdir -p audio/eval_30
```

### 4.2 방법 A: SOX / FFmpeg를 이용한 명령행 녹음 (macOS 권장)
마이크를 연결한 후 아래 명령어로 1문장씩 녹음할 수 있습니다 (예: 5초간 녹음):
```bash
# FFmpeg를 이용한 16kHz 모노 녹음 예시
ffmpeg -f avfoundation -i ":0" -ar 16000 -ac 1 -t 5 audio/eval_30/P01.wav

# SOX (rec) 명령어를 이용한 녹음 예시
rec -r 16000 -c 1 audio/eval_30/P01.wav trim 0 5
```

### 4.3 방법 B: QuickTime Player 또는 녹음 앱 사용
1. QuickTime Player 실행 $\to$ `새로운 오디오 녹음`
2. 문장을 읽고 녹음 완료 $\to$ 저장
3. 저장된 파일을 16kHz WAV로 변환하여 `audio/eval_30/P01.wav` 등으로 저장:
   ```bash
   ffmpeg -i "녹음파일.m4a" -ar 16000 -ac 1 -c:a pcm_s16le audio/eval_30/P01.wav
   ```

### 4.4 오독(말실수) 처리 및 정답 수정 원칙
- 녹음 도중 실수로 단어를 빠뜨리거나 다르게 읽은 경우:
  - **원칙 1**: 다시 녹음하는 것을 권장합니다.
  - **원칙 2**: 다시 녹음하기 어려운 경우, **평가 실행 전**에 사람이 실제 발화한 내용대로 정답 텍스트를 검수하여 커스텀 매니페스트(`audio/eval_30/manifest.json`)에 기록합니다.
  - **원칙 3 (절대 금지)**: **STT 인식 결과를 확인한 뒤에 인식 오류를 피하려고 정답 텍스트를 사후 수정하는 행위는 엄격히 금지됩니다.**

## 5. 30문장 CER 평가 도구 실행

녹음 파일(`P01.wav` ~ `P30.wav`)이 준비되면 아래 명령어로 평가를 실행합니다:

```bash
# 기본 평가 실행 (Direct STT 및 VAD+STT 동시 비교 평가)
.venv/bin/python scripts/evaluate_cer.py --audio-dir audio/eval_30

# 사람이 검수한 매니페스트가 있는 경우
.venv/bin/python scripts/evaluate_cer.py --audio-dir audio/eval_30 --manifest-json audio/eval_30/manifest.json
```

### 출력 결과 예시:
- 각 파일의 SHA-256 해시값과 길이 검증
- Direct STT(순수 음향 모델) vs VAD+STT(경계 절단 포함) 인식 결과 비교
- 공백 제거 Corpus CER (주 지표, 목표 $\le$ 15.0%) 산출
- 결과는 독립된 타임스탬프 JSON 파일(`logs/cer_eval_results_YYYYMMDD_HHMMSS_*.json`)에 보존됩니다.

## 6. 10분 연속 마이크 안정성 평가 실행

### 6.1 실행 요령
- 10분 동안 실제로 발표를 진행하며 마이크 입력을 테스트합니다 (단순 1문장 발화 후 9분 무음 방치는 검증에서 탈락 처리됩니다).
- 준비한 발표 자료(프로젝트 설명, 논문 발표, 자유 기술 주제)를 10분 동안 자연스럽게 발표합니다.

### 6.2 실행 명령어
```bash
# 600초 (10분) 마이크 실사용 안정성 평가 실행
.venv/bin/python tests/test_mic_10min.py --duration 600.0
```

### 6.3 평가 검증 기준:
1. **발화 분포 검증**: 10분 중 최소 5개 이상의 분(minute) 동안 유의미한 발화(분당 3초 이상)가 감지되어야 함.
2. **무손실 검증**: Overrun 0건, Chunk 누락 0건, Segment 누락 0건.
3. **메모리 안정성**: 부모 RSS와 자식 RSS가 점진적으로 폭증(Memory Leak)하지 않는지 스냅샷 확인.
4. **결과 저장**: `logs/task_01_mic_10min_YYYYMMDD_HHMMSS_*.json`에 자동 보존.

## 7. 로컬 오프라인 (네트워크 차단) 격리 환경 검증 안내

본 프로젝트의 STT/VAD는 100% 로컬 ONNX 모델로 구동됩니다. 이를 물리적으로 검증하려면 아래 방법 중 하나를 선택하여 외부 네트워크 송수신이 전혀 발생하지 않음을 확인할 수 있습니다.

### 방법 1: 물리적 네트워크 해제 (가장 확실하고 권장됨)
1. Wi-Fi를 끄거나 이더넷 케이블을 분리합니다.
2. `scripts/evaluate_cer.py` 또는 `tests/test_mic_10min.py`를 실행합니다.
3. 네트워크 연결이 전혀 없는 상태에서도 전사와 인식이 완벽히 수행됨을 확인합니다.

### 방법 2: macOS Packet Filter (pfctl) 격리 (고급)
사용자 계정 권한이 있을 경우 로컬 루프백(`lo0`)을 제외한 외부 egress를 차단할 수 있습니다:
```bash
# 테스트 종료 후 반드시 pfctl 비활성화 필요
sudo pfctl -d
```
> [!NOTE]
> 테스트 하네스의 Python `socket.connect` 차단 테스트는 통과(`Smoke PASS`)되었으나, OS 커널 수준의 완전 차단 증거는 사용자의 물리적 오프라인 확인 시 최종 인정됩니다.
