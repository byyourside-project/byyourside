# Task 01 — 사용자 음성 녹음 및 실사용 평가 가이드 (Revision 01)

본 문서는 **Task 01 (한국어 음성인식 파이프라인 PoC)**의 최종 실사용 성능을 검증하기 위해 사용자가 직접 수행하는 **30문장 발표 데이터셋 녹음** 및 **10분 연속 발표 마이크 평가** 가이드입니다.

---

## 1. 개요 및 평가 기준

### 1.1 평가 목표
1. **한국어 발표 음성 인식 정확도 (30문장 데이터셋)**:
   - **주 지표 (Primary Metric)**: **공백/문장부호 제거 Corpus CER $\le$ 15.0%**
     $$\text{Corpus CER} = \frac{\sum \text{Levenshtein Distance}}{\sum \text{Reference Characters}}$$
   - **보조 지표**: 공백 포함 CER, 카테고리별(일반, 숫자/단위, 전문용어/영문, 급변구간) CER, Direct STT vs VAD+STT 비교.
   - **표준 문항 요건**: P01 ~ P30 총 30개 고유 ID 전수 검증 필수 (1개, 29개 등 부분 집합만으로는 PASS 불가).
2. **10분 마이크 연속 발화 안정성**:
   - **무손실 스트리밍**: 오버런(Overrun) 0건, 청크 누락(Chunk Drop) 0건, 세그먼트 누락 0건.
   - **실시간성 (RTF)**: p95 RTF $\le$ 0.5 (오디오 1초당 추론 시간 0.5초 이하).
   - **큐 지연 안정성**: 큐 적체(Runaway Queue Drift) 없음 (드리프트 $\le$ 200ms 및 급격한 중간 서지 없음, 전 세그먼트 유효 수치 필수).
   - **연속 발화 분포**: 10분 중 최소 5개 이상의 분(minute)에 걸쳐 실제 발표 발화가 분포해야 함 (무음 방치 불가).
3. **발화 종료 후 인식 지연**:
   - VAD 감지 종료 기준 지연 p95 $\le$ 1.5초 (사람 청취 기준 정답 라벨링 병행).

### 1.2 예상 소요 시간
- **30문장 녹음 및 검수**: 약 **15 ~ 25분** (문장당 약 30~45초 소요: 낭독, 저장 및 재생 확인).
- **10분 마이크 연속 발표 시험**: 약 **15분** (발표 자료 준비, 10분 발표 실행, 지표 확인).

## 2. 녹음 규격 및 오디오 환경 설정

| 항목 | 권장 사양 | 허용 범위 및 처리 방식 |
| :--- | :--- | :--- |
| **샘플 레이트** | **16,000 Hz (16 kHz)** | 48,000 Hz 등 타 샘플 레이트는 파이프라인에서 다상 필터(`resample_poly`)로 자동 변환 |
| **채널** | **1 채널 (모노, Mono)** | 스테레오/다채널 입력 시 채널별 산술 평균(`(L + R) / 2.0`)으로 모노 다운믹스 |
| **비트 심도** | **16-bit signed PCM** | 24-bit / 32-bit float PCM 자동 정규화 ([-1.0, 1.0] 범위) |
| **포맷** | **RIFF WAV (`.wav`)** | 표준 무압축 PCM WAV |
| **녹음 환경** | 조용한 실내 (에어컨, 선풍기, 키보드 타자음 등 환경 소음 최소화) |
| **발화 속도** | 평소 발표하는 자연스러운 속도 (약 분당 300~350음절) |
| **저장 위치** | 프로젝트 루트 기준 `audio/eval_30/` 디렉터리 (`P01.wav` ~ `P30.wav`) |

### 2.1 마이크 선택 및 발화 유의사항
- **입력 장치 선택**: macOS의 경우 `시스템 설정` $\to$ `사운드` $\to$ `입력`에서 사용할 외장 마이크 또는 내장 마이크를 기본 장치로 설정합니다.
- **음성 전후 여유 구간(Padding)**: 녹음 시작 직후와 종료 직전에 약 **0.5초의 정적(Silence)**을 둔 상태에서 발화해 주십시오 (첫음절/끝음절 절단 방지).
- **문장 중간 쉼(Pause) 및 최대 발화 길이**:
  - 문장 중간에 0.5초 이상의 침묵을 두면 VAD가 별개의 세그먼트로 분할합니다.
  - 파이프라인의 안전 보호 한도(Hard max speech duration)는 **4.0 ~ 5.0초**이므로, 한 호흡에 5초를 초과하여 쉬지 않고 연속 발화하지 않도록 자연스러운 쉼표 호흡을 유지해 주십시오.

## 4. 실제 녹음 방법 및 매니페스트 관리

### 4.1 녹음 준비 (폴더 생성)
터미널에서 녹음 대상 디렉터리를 생성합니다:
```bash
mkdir -p audio/eval_30
```

### 4.2 방법 A: FFmpeg 또는 SOX를 이용한 명령행 녹음 (macOS 권장)
마이크를 연결한 후 1문장씩 녹음할 수 있습니다 (예: 5초간 녹음):
```bash
# FFmpeg를 이용한 16kHz 모노 녹음 예시
ffmpeg -f avfoundation -i ":0" -ar 16000 -ac 1 -t 5 audio/eval_30/P01.wav

# SOX (rec) 명령어를 이용한 녹음 예시
rec -r 16000 -c 1 audio/eval_30/P01.wav trim 0 5
```

### 4.3 방법 B: QuickTime Player 또는 녹음 앱 사용
1. QuickTime Player 실행 $\to$ `새로운 오디오 녹음`
2. 문장을 읽고 녹음 완료 $\to$ 저장
3. 저장된 파일을 16kHz 모노 WAV로 변환하여 `audio/eval_30/P01.wav` 등으로 저장:
   ```bash
   ffmpeg -i "녹음파일.m4a" -ar 16000 -ac 1 -c:a pcm_s16le audio/eval_30/P01.wav
   ```

### 4.4 오독(말실수) 처리 및 매니페스트(`manifest.json`) 작성 규칙
- 녹음 도중 실수로 단어를 빠뜨리거나 다르게 읽은 경우:
  - **원칙 1**: 다시 녹음하는 것을 가장 권장합니다.
  - **원칙 2**: 다시 녹음하기 어려운 경우, **평가 실행 전**에 사람이 실제 발화한 내용대로 정답 텍스트를 검수하여 매니페스트(`manifest.json`)를 작성합니다.
  - **원칙 3 (절대 금지)**: **STT 인식 결과를 확인한 뒤에 인식 오류를 피하려고 정답 텍스트를 사후 수정하는 행위는 엄격히 금지됩니다.**
  - **원칙 4 (정답 유효성 요건)**: 정답 텍스트(`ref`)는 반드시 문자열이어야 하며, 문장부호 및 공백 제거 정규화 후 최소 1글자 이상의 유효 한글/영문/숫자를 포함해야 합니다. 공백만 있거나(`"   "`), 문장부호만으로 구성된(`".,!?"`) 정답은 모델 추론 시작 전에 즉시 `ERROR`로 거부됩니다.

#### 매니페스트 JSON 예시 (`manifest.json`) 및 모드별 동작 정책:
매니페스트는 두 가지 모드를 지원합니다:
1. **완전 목록 모드 (`mode: "complete"`, 기본값)**:
   - 매니페스트에 나열된 항목만을 전사 평가 대상으로 삼습니다.
   - P01~P30 30개 고유 ID가 모두 포함되어 있어야 전체 `PASS`가 가능합니다. 만약 1개나 29개 등 부분 목록만 제공되면, 해당 항목들에 대한 CER 평가는 정상 수행되지만 표준 30문항 커버리지 미충족으로 종합 판정은 `PARTIAL`로 기록되며 결코 전체 `PASS`가 될 수 없습니다. (입력을 무조건 거부하는 것이 아니라 부분 실행 `PARTIAL`로 안전 처리).
2. **병합 수정 모드 (`mode: "merge"`)**:
   - 오독 등으로 수정한 문항만 지정하며, 지정되지 않은 나머지 문항은 표준 30문장 정답을 자동으로 유지하여 30문항 전수 평가를 완결합니다.

```json
{
  "version": "1.0",
  "mode": "merge",
  "description": "사용자 발화 정답 수정 매니페스트 (수정 항목만 기재)",
  "items": [
    {
      "id": "P09",
      "category": "numbers_units",
      "ref": "전체 응답 속도는 십오 밀리세컨드 단축되었습니다."
    },
    {
      "id": "P11",
      "category": "numbers_units",
      "ref": "총 삼십개의 평가 문항을 준비했습니다."
    }
  ]
}
```
> [!NOTE]
> 매니페스트 경로를 `--manifest-json`으로 지정했을 때 해당 파일이 없거나 JSON 형식/중복 ID/공백 정답 오류가 있으면 조용히 기본값으로 대체되지 않고 모델 시작 전에 즉시 명시적 에러(`ERROR`) 보고서를 생성합니다.

## 5. 30문장 CER 평가 도구 실행

녹음 파일(`P01.wav` ~ `P30.wav`)이 준비되면 아래 명령어로 평가를 실행합니다:

```bash
# 기본 평가 실행 (Direct STT 및 VAD+STT 동시 비교 평가, 격리된 고유 로그 자동 생성)
.venv/bin/python scripts/evaluate_cer.py --audio-dir audio/eval_30

# 사람이 검수한 매니페스트가 있는 경우
.venv/bin/python scripts/evaluate_cer.py --audio-dir audio/eval_30 --manifest-json audio/eval_30/manifest.json

# 특정 출력 파일 지정 시 (기존 파일이 존재하면 덮어쓰지 않고 고유 경로로 자동 보존)
.venv/bin/python scripts/evaluate_cer.py --audio-dir audio/eval_30 --output-json logs/my_eval.json

# 기존 파일을 명시적으로 교체하고자 할 경우
.venv/bin/python scripts/evaluate_cer.py --audio-dir audio/eval_30 --output-json logs/my_eval.json --overwrite
```

### 5.1 출력 결과 보호 및 지표 해석
- **기존 출력 파일 보호 정책**: `--output-json`으로 지정한 파일이 이미 존재하는 경우, 이전 평가 증거를 보존하기 위해 기본적으로 덮어쓰지 않고 `my_eval_YYYYMMDD_HHMMSS_<uuid>.json` 형태로 새 고유 경로에 저장됩니다 (`--overwrite` 플래그로만 명시적 교체 허용).
- **상태 구분**:
  - `NOT_RUN`: 녹음 파일이 존재하지 않음 (0/30).
  - `PARTIAL`: 파일 일부만 존재하거나, 매니페스트 문항이 30개 미만인 경우.
  - `ERROR`: 오디오 파일이 존재하지만 런타임 추론 예외(Timeout 등)가 발생한 경우.
  - `FAIL`: 30문항 모두 전사되었으나 주 지표 CER이 15.0%를 초과한 경우.
  - `PASS`: 30문항 전수 평가 완료 및 공백 제거 Corpus CER $\le$ 15.0%.
- **`boundary_cer_diff`**: Direct STT CER 대비 VAD+STT CER의 차이를 의미하며, VAD 구간 분할과 발화 경계 컨텍스트 영향도를 비교하는 참고 지표입니다 (음향학적 정밀 정렬 없는 단독 절단 손실 증명으로 단정하지 않음).
- **CLI Exit Code**:
  - `0`: 전체 검증 PASS.
  - `1`: FAIL 또는 ERROR.
  - `2`: NOT_RUN 또는 PARTIAL (녹음 파일 미완료 또는 부분 실행).

## 6. 10분 연속 마이크 안정성 평가 실행

### 6.1 실행 요령
- 10분 동안 실제로 발표를 진행하며 마이크 입력을 테스트합니다.
- 단순 1문장 발화 후 9분 무음 방치는 발화 분포 검증에서 `PARTIAL / INSUFFICIENT`로 처리되어 정식 통과되지 않습니다.
- 준비한 발표 자료(프로젝트 설명, 논문 발표, 자유 기술 주제)를 10분 동안 자연스럽게 발표합니다.

### 6.2 실행 명령어
```bash
# 600초 (10분) 마이크 실사용 안정성 평가 실행 (고유 격리 로그 자동 생성)
.venv/bin/python tests/test_mic_10min.py --duration 600.0

# 특정 파일 지정 시 (기존 파일이 존재하면 보호를 위해 새 고유 파일명으로 자동 분기)
.venv/bin/python tests/test_mic_10min.py --duration 600.0 --output-json logs/my_mic.json

# 기존 파일을 명시적으로 교체하고자 할 경우
.venv/bin/python tests/test_mic_10min.py --duration 600.0 --output-json logs/my_mic.json --overwrite
```

### 6.3 평가 검증 기준 및 게이트 분리:
1. **자원 및 스트리밍 안정성 (`resource_and_streaming_stability`)**:
   - Overrun 0건, Chunk 누락 0건, Segment 누락 0건.
   - 큐 적체(Runaway Drift > 200ms 또는 서지) 없음 (전 세그먼트 유효 수치 필수).
   - 부모 프로세스 및 자식 추론 프로세스 RSS 메모리 누수 없음.
2. **지연 및 실시간성 (`latency_and_rtf_performance`)**:
   - p95 RTF $\le$ 0.5 및 VAD 종료 기준 추론 지연 p95 $\le$ 1.5초.
3. **입력 존재 확인 (`speech_input_presence`)**:
   - 10분 중 최소 5개 이상의 분(minute) 동안 유의미한 발화 감지 (총 60초 이상).
   - *주의: 최소 발화 조건 충족은 음성 입력이 유효했음을 나타내는 진단 기준이며, 10분 발표 연속성 완결의 직접 증거는 아닙니다.*
4. **발표 연속성 및 사람 기준 지연 (게이트 분리)**:
   - 발표 연속성 적합성(`continuous_presentation_coverage`) 및 사람 청취 기준 종료 지연(`human_reference_speech_end_latency`)은 사용자 및 PM 검토 대상으로서 `PARTIAL`로 유지됩니다.
   - 이에 따라 `technical_stability_passed`는 기술 지표 통과 시 `True`가 되지만, 전체 게이트 `passed`는 연속 발표 및 주석 완료 전까지 `False`(`overall_status: PARTIAL`)로 명확히 분리됩니다.
5. **예외 및 기존 파일 보존**:
   - 실행 도중 예외가 발생하더라도 `logs/task_01_mic_10min_*.json`에 실패 단계(`failed_phase`), 예외 내용, 수집된 지표를 안전하게 저장합니다.
   - 기존 결과 파일이 지정되어 있더라도 실패 기록 때문에 이전 파일이 덮어씌워지지 않도록 보호됩니다.

## 7. 로컬 오프라인 (네트워크 차단) 격리 환경 검증 안내

본 프로젝트의 STT(SenseVoice ONNX) 및 VAD(Silero ONNX)는 외부 통신 없이 **100% 온디바이스(로컬 프로세스)**에서 구동됩니다. 이를 확인하기 위한 네트워크 격리 절차는 아래와 같습니다.

### 7.1 활성 네트워크 경로 확인
격리 전 현재 시스템의 활성 네트워크 인터페이스를 확인합니다:
```bash
# 활성 네트워크 인터페이스 확인
ifconfig -u

# 기본 게이트웨이 라우트 확인
route get default
```

### 7.2 안전한 물리적/소프트웨어 네트워크 차단 절차
1. **Wi-Fi 비활성화**:
   - macOS 상단 메뉴 막대의 제어 센터에서 Wi-Fi를 끄거나, 터미널에서 다음 명령어를 실행합니다:
     ```bash
     networksetup -setairportpower en0 off
     ```
     *(Wi-Fi 인터페이스가 en0이 아닌 경우 `networksetup -listallhardwareports`로 확인)*
2. **유선 이더넷 케이블 분리**: 유선 LAN 어댑터 케이블을 분리합니다.
3. **모바일 핫스팟/테더링 및 VPN 해제**: iPhone/Android USB 테더링을 해제하고 활성화된 VPN 앱을 종료합니다.
4. **차단 상태 확인**:
   ```bash
   # 외부 핑 및 HTTP 요청 실패 확인
   ping -c 1 8.8.8.8
   curl -I https://www.google.com
   # 출력: Network is unreachable 또는 Could not resolve host
   ```
5. **오프라인 상태에서 STT 파이프라인 실행**:
   ```bash
   .venv/bin/python scripts/evaluate_cer.py --audio-dir audio/eval_30
   ```
6. **네트워크 원상 복구**:
   - 평가 종료 후 Wi-Fi를 다시 활성화합니다:
     ```bash
     networksetup -setairportpower en0 on
     ```
   - 이더넷 케이블 및 필요 서비스를 다시 연결합니다.

> [!CAUTION]
> 시스템 전역 패킷 필터(`pfctl`) 설정을 임의로 변경하거나 무조건 비활성화(`pfctl -d`)하는 것은 기존 방화벽 규칙을 손상시킬 수 있으므로 권장하지 않으며 본 절차에서 제외되었습니다.

> [!NOTE]
> 로컬 오프라인 실행 성공은 인터넷 연결이 단절된 상태에서도 파이프라인이 100% 정상 작동함을 입증하는 것이며, OS 커널 수준의 송신 시도 0건 보증(egress blocking)과는 구분됩니다. (Task 01 현재 OS egress blocking은 PARTIAL 상태로 유지됩니다.)
