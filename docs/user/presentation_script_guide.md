# 대본·슬라이드 기반 발표 코칭 사용법

업데이트: 2026-10-16

## 실행과 준비

기본 모델은 **Llama 3.1 8B (`llama3.1:8b`)**다. STT → 로컬 LLM 흐름을 유지한다. Ollama 서버가 실행 중이어야 하며, 모델은 처음 한 번 별도로 설치한다. 발표 서버가 모델을 자동으로 다운로드하지는 않는다.

```bash
ollama pull llama3.1:8b
.venv/bin/python scripts/run_presentation.py --coach-timeout 6
```

`--ollama-model llama3.1:8b`로 명시할 수도 있다. 기존 모델을 비교하려면 설치된 `qwen3:8b`를 `--ollama-model`로 지정한다. 검증 스크립트도 기본적으로 Llama 3.1을 사용하며 `--model qwen3:8b`로 바꿀 수 있다. 실행 로그와 발표 기록의 모델 정보로 실제 사용 모델을 확인한다. 모델 파일은 Ollama의 로컬 저장소에 설치되며 Git 저장소에는 포함하지 않는다.

Llama의 대본 추적에는 전용 지시문과 고정 예시를 적용한다. 개발용 문장 추적 6개 사례에서 평균 모델 요청 시간은 3.74초였으며, 마이크부터 화면까지의 전체 지연이나 정확도 향상을 보장하지 않는다. 자세한 범위는 [Llama 적용·검증 기록](../reports/presentation_llama31.md)을 참고한다.

기본 주소는 `http://127.0.0.1:8765`다. 새 기본 예제는 `examples/presentation_slides_script.txt`와 `examples/presentation_slides_deck.json`이다. 기존 단일 대본 예제와 일반 슬라이드 JSON도 계속 사용할 수 있다.

1. **대본 넣기**에 한 줄에 한 문장씩 입력한다. 마침표 뒤 공백도 문장 경계로 사용한다. 최대 20,000자/50문장, 문장당 1,000자다.
2. 슬라이드 사이에 `<<슬라이드 넘김>>`을 넣는다. 이 표시는 읽지 않으며 문장 수·글자량·시간 배정에서 제외한다. 표시 앞뒤에 빈 슬라이드를 만들 수 없다. 표시가 없으면 한 슬라이드다.
3. 전체 목표 시간을 입력한다. **슬라이드별 목표 시간**을 비워 두면 글자량에 비례해 배정한다. 그림 설명이나 시연을 반영하려면 `60, 90, 30`처럼 입력한다. 합계는 전체 목표 시간과 같아야 한다.
4. **대본 준비 · 시간 계산**을 누르고 슬라이드 수와 목표 시간을 확인한다.
5. 마이크를 선택하고 **마이크 입력 확인**으로 장치를 확인한다. 실제 음성 없이 기능을 시험하려면 입력 방식을 **직접 전사 입력**으로 바꾼 뒤 시작한다.
6. 음성 안내는 기본 꺼짐이다. 이어폰과 출력 장치를 확인한 뒤 켠다. **빠름·느림만**은 슬라이드 시간 안내를, **전체 안내**는 기존 잔여 시간·내용 확인 안내도 읽는다.

```text
오늘 발표의 목적을 소개합니다.
음성 인식은 기기 안에서 실행합니다.
<<슬라이드 넘김>>
실험 결과를 설명하겠습니다.
전체 처리 시간은 4초입니다.
```

## 문장 위치와 내용 확인

현재 문장과 다음 3문장을 이동 후보로 전달한다. 앞선 최대 2문장도 내용 검토용으로 포함하지만 자동으로 뒤로 이동하지 않는다. 최근 STT 문맥은 최대 45초/12구간/2,400자를 유지한다. 대본 모드에서는 발화 구간 번호를 보존하고 LLM이 여러 조각의 근거를 함께 선택하게 한다.

LLM은 내용 확인 결과와 별도로 **문장 위치 / 말하는 중·발화 완료 / 근거 발화**를 반환한다. 예를 들어 대본의 숫자와 전사의 숫자가 달라도 관련 문장을 특정할 수 있다면 위치는 이동할 수 있다. 내용은 판단불가로 남는다. 위치 이동으로 지나온 문장을 자동 완료 처리하지 않는다. 화면의 **현재 문장**과 **내용 일치 확인 비율**은 서로 다른 값이다.

후보가 불명확하거나 해당 문장이 없으면 이동하지 않는다. 내용 검토에서도 미언급인 항목을 위치로 고른 모순된 응답은 무시한다. 두 번 연속으로 위치를 찾지 못하면 현재 슬라이드의 뒤쪽 문장까지 탐색 범위를 넓힌다. 동일한 문장이 반복되면 잘못된 앞으로 이동을 보류한다. 추적이 어긋나면 해당 문장의 **여기서 이어가기**로 직접 맞춘다.

수동 위치 보정은 내용을 완료 처리하지 않고, 이미 실행 중이거나 대기 중이던 이전 위치 판단을 무효화한다. LLM 실행 중 새 음성이 들어와도 더 최근 위치 결과를 덮어쓰지 않는 이전 판단은 반영할 수 있다. 대기 중 요청의 후보는 실제 추론 시작 시 현재 위치를 기준으로 갱신한다.

긴 대본의 복구 탐색은 입력량과 지연을 늘릴 수 있다. 모델 컨텍스트 한도나 요청 제한에 걸리면 오류를 기록하고 판단을 보류한다. 직접 위치 선택으로 범위를 줄일 수 있다. 6초는 요청 제한이며 실시간 응답 보장이 아니다.

## 슬라이드와 시간 안내

다음 슬라이드의 발화가 확인되면 해당 발화의 시작 시각을 경계로 추정한다. 실제 PPT/PDF 페이지를 자동으로 넘기거나 실제 페이지 상태를 읽는 기능은 포함하지 않는다.

- **이전·다음 / 슬라이드 목록 버튼**: 실제 슬라이드를 바꿀 때 누르면 누른 시각을 전환 시각으로 기록한다.
- **여기서 이어가기**: 추적 위치 보정이다. 다른 슬라이드로 보정한 경우 실제 전환 시점을 알 수 없으므로 경계가 불명확한 기록으로 남긴다.
- 이전·다음 슬라이드의 문장이 한 STT 구간에 섞이거나 여러 슬라이드를 한꺼번에 건너뛴 경우, 문장 위치는 찾더라도 경계 시간 판단은 보류한다.

화면은 현재 대본 위치를 기준으로 시간 진행을 추정한다. 지나온 문장을 실제로 모두 설명했다는 뜻은 아니다. 별도의 내용 확인 상태를 함께 살핀다. 시간 계산은 LLM 밖에서 수행하며 녹음 시각 또는 직접 전환 이벤트를 사용한다. 모델 응답 대기 시간을 추가하지 않는다. 경과 시간에는 발표 중 쉬거나 덧붙여 설명한 시간도 포함한다.

화면 상단의 **지금 발표 속도** 카드는 발표 중 스크롤해도 보인다. **발표 시작**을 누르면 이 영역으로 이동한다. 큰 글씨와 게이지로 빠름·계획 범위·느림을 표시하며, **100%가 계획 속도**다. 현재 슬라이드에서 해당 대본 위치까지 배정된 시간 ÷ 해당 발화 종료까지 소요된 시간으로 계산한다. 125% 초과는 빠름, 75% 미만은 느림이며, 계획보다 몇 초 앞서거나 뒤처졌는지도 함께 표시한다. 이는 현재 슬라이드 기준 차이이며 아래 표의 전체 계획 차이와 기준이 다르다.

슬라이드 남은 시간은 화면 조회 주기(약 0.2초)에 따라 갱신한다. 속도는 모델의 위치 판단이 도착하면 갱신하며 **몇 초 전 발화 기준**인지 표시한다. 최신 발화를 처리하는 동안 유효한 직전 속도는 유지하지만, 근거가 15초보다 오래됐거나 위치가 불명확하거나 입력 오류가 있으면 속도 안내를 보류한다. 수동 위치 보정 후에는 새 발화 확인을 기다린다. 서버 연결이 끊어지면 속도와 남은 시간 숫자를 숨겨 갱신 중단을 알린다. 종료 후 카드는 마지막 슬라이드의 실제 체류 시간과 목표 시간을 비교한다. 이 화면 추가로 STT·LLM 추론 지연 자체가 줄어드는 것은 아니다.

음성은 슬라이드 전환 시 직전 슬라이드에 대해 방문당 최대 한 번만 나온다. 목표 시간 ÷ 실제 소요가 125%를 넘거나 75%보다 작을 때 안내한다. 계획 범위 안이거나 경계가 불명확하면 음성 안내를 하지 않는다. 예: **“직전 1번 슬라이드를 계획보다 20초 일찍 마쳤습니다.”** 실제 발음 속도를 단정하거나 무조건 천천히 말하라고 지시하지 않는다.

새 발화를 처리해도 직전 슬라이드의 유효한 요약은 유지한다. 다음 전환, 만료, 음성 끄기·범위 변경, 발표 종료 시 지난 안내를 취소한다. 마지막 슬라이드는 **발표 종료**를 누른 시각까지 정산하고 종료 결과 표에 표시한다. 종료 후 새 음성을 재생하지 않는다.

## 저장과 검증

**발표 종료 → 기록 저장**으로 JSON을 받는다. 원문, `script_plan.slides`, 위치 상태 `script_progress.tracking`, 시간 기록 `script_progress.slide_timing.records`, 문장별 내용 확인, 원본 발화·이벤트를 저장한다. 내부 음성 근거는 경계를 넘는 발화도 다루기 위해 하나의 연속 대본 스트림으로 유지하며 논리 슬라이드는 `script_plan.slides`에서 구분한다. 기존 문장별 시간 진단 필드는 호환성을 위해 보존한다.

마이크 오류가 나면 장치를 확인하고 **마이크 다시 연결**을 누른다. 오류와 손실 기록은 보존하며 임의로 직접 전사 모드로 바꾸지 않는다. STT 시간 초과의 기존 제한 재시도 정책은 유지한다.

```bash
.venv/bin/python -m unittest discover -s tests
node tests/test_presentation_ui.cjs
.venv/bin/python scripts/validate_script_tracking.py
```

마지막 명령은 설치된 로컬 모델에 텍스트 사례를 재생한다. 마이크 녹음이나 이어폰 청취 검증을 의미하지 않는다. 수치 오류·부분 발화·무관한 발화·반복 문장·긴 생략·슬라이드 경계·수동 보정을 실제 낭독으로도 확인하는 것이 좋다. 스피커 안내의 마이크 재유입과 장시간 동시 부하 성능은 별도 시험 대상이다.
