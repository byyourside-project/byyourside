# 대본 기반 발표 코칭 사용법

1. 로컬 Ollama 서버가 켜져 있고 `qwen3:14b`가 설치된 맥에서 실행한다.

```bash
.venv/bin/python scripts/run_presentation.py --ollama-model qwen3:14b --coach-timeout 8
```

2. `http://127.0.0.1:8765`에서 **대본 넣기**에 대본을 붙여 넣고 목표 시간을 초 단위로 입력한다. **대본 준비 · 시간 계산**을 누른다. 기본 예제 대본은 `examples/presentation_script.txt`이며 화면에도 채워져 있다.
3. 한 줄에 한 문장을 쓰면 추적 구간이 명확하다. 마침표 뒤 공백도 문장 경계로 사용한다. 최대 20,000자/50구간, 한 구간 1,000자다. 모든 구간을 필수로 취급한다. JSON 자료를 불러오는 기존 모드도 사용할 수 있다.
4. 발표 전에 구간별 예정 시간과 분당 글자 기준을 확인한다. 글자는 공백·문장부호 제외 기준이며 발음 음절 수가 아니다. 숫자/영문 낭독과 실제 멈춤을 반영한 리허설 보정은 아직 자동 지원하지 않는다.
5. 이어폰을 연결하고 macOS의 출력 장치가 이어폰인지 확인한다. **이어폰 음성 안내**를 켜고 마이크를 선택한 뒤 **발표 시작**을 누른다. **안내 음성 시험**을 눌러 실제로 들리는지 확인한다. 음성 안내는 기본 꺼짐이며 켜기/끄기가 가능하다. macOS의 설치된 Yuna 음성을 로컬 `say`로 재생한다. 다른 OS/보드용 TTS는 이 구현에 포함되지 않는다.
6. 대본을 설명하면 현재 확인 위치, 다음 예정 내용, 설명 확인률을 표시한다. 등록 문장을 그대로 읽는 것과 바꿔 말하기는 의미 모델로 판단한다. 문장 매칭 기본 모드는 오타/바꿔 말하기를 놓칠 수 있다.
7. 중간 구간을 건너뛰고 두 개의 뒤쪽 구간 또는 마지막 구간까지 설명되면 건너뛴 내용 확인 안내를 제공한다. 판단불가는 확정 누락으로 부르지 않는다. 늦게 설명한 구간은 안내를 철회한다. 대본 모드는 수동 슬라이드 전환 없이 하나의 연속 대본으로 진행한다.
8. 진행 속도는 확인된 고유 대본량/전체 경과 시간과 사전 계획을 비교한다. 반복 낭독으로 진행량이 늘지 않는다. 최소 15초, 대본 10% 이상 확인되고 계획 대비 25% 이상 차이가 5초 유지될 때 빠름/느림을 안내한다. 최대 최근 15초 내 내용 확인 근거가 필요하며 미해결 구간·품질 문제·판단 대기 중에는 보류한다. 일반적인 적정 발음 속도를 판정하는 기능은 아니다.
9. 음성 안내는 화면 알림과 동일한 내용이다. 큐·재생 시작·완료·취소·실패를 저장한다. 상태나 속도가 바뀌거나 지난 안내는 재생을 취소한다. 음성 재생 완료는 운영체제 프로세스의 정상 종료이며 사용자가 실제로 들었다는 증거는 아니다.
10. **발표 종료 → 기록 저장**으로 JSON을 받는다. 대본·시간 계획·근거·진행 상태·누락 후보·음성 재생 이벤트가 들어 있다.

모델 요청 제한 8초는 최대 대기값이며 실시간 성능 보장이 아니다. 마이크와 LLM 동시 부하에서 지연이 늘 수 있다. 스피커 안내가 다시 STT로 인식되는 루프는 별도 실제 시험이 필요하다. 마이크를 끄는 방식으로 발화 손실을 숨기지 않는다.

## 빠른 기능 시험

- 정상: 모든 구간을 순서대로 설명한다.
- 누락: 두 번째 구간을 생략하고 뒤의 두 구간을 설명한다. 두 번째 구간 안내 후 다시 설명해서 철회를 확인한다.
- 속도: 동일한 대본에 짧은 목표 시간/긴 목표 시간을 각각 설정하고 실제 진행한다. 최소 관측 및 지속 조건 이후의 빠름/느림 안내를 확인한다.
- 오인식/정정: 부정·잘못된 수치·정정은 설명됨으로 자동 승인되지 않는지 확인한다.
- 음성: 이어폰에서 안내를 듣고 음성 안내를 끄면 재생이 멈추는지 확인한다.
