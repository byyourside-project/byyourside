# 대본 기반 발표 코칭 사용법

1. 로컬 Ollama 서버가 켜져 있고 `qwen3:8b`가 설치된 맥에서 실행한다.

```bash
.venv/bin/python scripts/run_presentation.py --ollama-model qwen3:8b --coach-timeout 6
```

2. `http://127.0.0.1:8765`에서 **대본 넣기**에 대본을 붙여 넣고 목표 시간을 초 단위로 입력한다. **대본 준비 · 시간 계산**을 누른다. 기본 예제 대본은 `examples/presentation_script.txt`이며 화면에도 채워져 있다.
3. 한 줄에 한 문장을 쓰면 추적 구간이 명확하다. 마침표 뒤 공백도 문장 경계로 사용한다. 최대 20,000자/50구간, 한 구간 1,000자다. 모든 구간을 필수로 취급한다. JSON 자료를 불러오는 기존 모드도 사용할 수 있다.
4. 발표 전에 구간별 예정 시간과 분당 글자 기준을 확인한다. 글자는 공백·문장부호 제외 기준이며 발음 음절 수가 아니다. 숫자/영문 낭독과 실제 멈춤을 반영한 리허설 보정은 아직 자동 지원하지 않는다.
5. 입력 방식에서 마이크를 선택하고 입력 장치를 고른 뒤 **마이크 입력 확인**을 누른다. 신호 세기와 연결 성공을 확인한다. 이어폰을 연결하고 macOS의 출력 장치가 이어폰인지 확인한다. **이어폰 음성 안내**를 켜고 안내 범위를 **빠름·느림만**으로 둔 뒤 **발표 시작**을 누른다. 진행 중에 **안내 음성 시험**을 눌러 들리는지 확인할 수 있다. 음성 안내는 기본 꺼짐이고 범위 기본값은 빠름·느림만이다. 기기가 음소거되어 있으면 안내를 들을 수 없으며 앱은 볼륨을 바꾸지 않는다. macOS의 설치된 Yuna 음성을 로컬 `say`로 재생한다. 다른 OS/보드용 TTS는 이 구현에 포함되지 않는다.
6. 대본을 설명하면 현재 확인 위치, 다음 예정 내용, 설명 확인률을 표시한다. 등록 문장을 그대로 읽는 것과 바꿔 말하기는 의미 모델로 판단한다. 모델이 미언급으로 응답해도 최신 완성 발화 전체가 대본 문장과 정확히 일치하면 보완한다. 모순·불확실 판단, 정정·질문·인용·미완성 문맥은 이 방식으로 확정하지 않는다. 문장 매칭 기본 모드는 오타/바꿔 말하기를 놓칠 수 있다.
7. 중간 구간을 건너뛰고 두 개의 뒤쪽 구간 또는 마지막 구간까지 설명되면 건너뛴 내용 확인 안내를 제공한다. 판단불가는 확정 누락으로 부르지 않는다. 늦게 설명한 구간은 안내를 철회한다. 대본 모드는 수동 슬라이드 전환 없이 하나의 연속 대본으로 진행한다.
8. 진행 속도는 확인된 고유 대본량을 **그 대본을 처음 확인한 실제 발화 종료 시각**으로 나눠 사전 계획과 비교한다. STT·모델 처리 지연은 속도 계산에서 제외한다. 반복 낭독으로 진행량이나 최초 측정 시각이 늘지 않는다. 발화 종료 기준 최소 15초, 대본 10% 이상 확인된 뒤 계획 속도의 125% 초과 또는 75% 미만 상태가 5초 유지되면 빠름/느림을 안내한다. 같은 방향 안내는 실제 안내 발생 시각부터 최소 30초 간격이다. 계획 내 속도에는 속도 음성 안내가 없다. 최근 15초 내 발화 근거가 필요하며 미해결 구간·품질 문제·판단 대기 중에는 보류한다. 일반적인 적정 발음 속도를 판정하는 기능은 아니다.
9. 화면의 **목표 시간과 진행 속도**에서 계획·현재 확인 속도, 계획 대비 비율, 예상 전체 시간과 보류 이유를 확인한다. 음성 범위 **빠름·느림만**은 속도 안내만 읽고, **전체 안내**를 선택하면 잔여 시간과 내용 확인 안내도 읽는다. 명시적인 음성 시험 버튼은 선택 범위와 관계없이 시험 안내를 읽는다. 큐·재생 시작·완료·취소·실패를 저장한다. 새 발화 처리, 상태·속도·범위 변경, 음성 끄기, 발표 종료 시 유효하지 않은 안내를 취소한다. 음성 재생 완료는 운영체제 프로세스의 정상 종료이며 사용자가 실제로 들었다는 증거는 아니다.
10. **발표 종료 → 기록 저장**으로 JSON을 받는다. 대본·시간 계획·근거·진행 상태·누락 후보·음성 재생 이벤트가 들어 있다.

기본 실행도 설치된 `qwen3:8b`를 사용한다. 모델 없는 등록 표현 시험은 `--phrase-coach`를 지정한다. 자동으로 모델을 다운로드하지 않는다. 이 맥에서 14B 모델을 메모리에 올렸을 때 macOS 오디오 버퍼 잠금 실패가 재현되어, 마이크 코칭 기본 모델을 줄였다.

마이크 오류 때는 입력 장치를 확인하고 **마이크 다시 연결**을 누른다. 재연결 전후 발화는 같은 세션에 기록하고 원래 실패도 보존한다. 입력 손실·STT 실패·모델 오류가 있으면 건너뛴 대본 안내를 철회하고 누락·속도 판단을 보류한다. 이후 발화의 내용 확인은 계속 가능하다. 필요하면 발표를 종료하고 새 발표를 시작한다. 오류가 나도 마이크 모드를 수동 전사 모드로 바꾸지 않는다.

모델 요청 제한 6초는 최대 대기값이며 실시간 성능 보장이 아니다. 마이크와 LLM 동시 부하에서 지연이 늘 수 있다. 스피커 안내가 다시 STT로 인식되는 루프는 별도 실제 시험이 필요하다. 마이크를 끄는 방식으로 발화 손실을 숨기지 않는다.

## 짧게 쉬거나 문장을 이어 말할 때

발표 마이크 모드는 0.3초 무음을 기준으로 발화를 STT에 보낸다. VAD의 판단 지연과 STT 시간이 추가되므로 0.3초가 화면 표시까지의 보장 시간은 아니다. 전사는 로컬 모델 판단과 독립적으로 먼저 표시한다.

1.5초 이내에 이어 말한 조각은 텍스트를 합쳐 판단하며, 원래 녹음 구간 ID를 근거로 모두 보존한다. 이전 문장도 같은 발표 구간의 최근 문맥에 포함한다. 입력은 최근 45초/12조각/2,400자 이내로 제한하고 제외한 문맥은 `context_trimmed` 이벤트로 남긴다. 단일 조각이 너무 길어 모델 입력 한도에 도달하면 판단을 보류한다. 무음이나 STT가 붙인 마침표를 실제 문장 종료로 단정하지 않는다.

모델이 완료로 답해도 “보내지 않고” 같은 명확한 미완성 어미이거나, 대본의 지원 숫자·단위를 발화에서 확인하지 못하면 판단을 보류한다. 숫자 검사는 대본의 아라비아 숫자를 전사의 아라비아·한국어 수사와 비교한다. 초·분·시간, 원, 퍼센트, 개·명·회에 적용하며 시간 환산을 지원한다. 다른 단위와 문장의 관계·부정 의미는 여전히 의미 모델이 판단한다. 이 검사는 완료를 승인하는 규칙이 아니며 숫자가 맞아도 내용 전체가 맞다는 보장은 없다.

STT 요청이 시간 초과하면 같은 음성을 한 번 재시도한다. 재시도도 실패한 구간은 오류와 손실로 기록하고 다음 발화 입력을 유지한다. 세 구간 연속으로 재시도까지 실패하면 음성 처리를 종료하고 오류를 표시한다. 복구 중에는 자식 프로세스 초기화 시간이 추가될 수 있고, 큐가 넘치는 경우도 손실 기록을 남긴다. 기준 성능 시험의 기본 실패 정책은 변경하지 않았다.

## 빠른 기능 시험

- 정상: 모든 구간을 순서대로 설명한다.
- 누락: 두 번째 구간을 생략하고 뒤의 두 구간을 설명한다. 두 번째 구간 안내 후 다시 설명해서 철회를 확인한다.
- 속도: 동일한 대본에 짧은 목표 시간/긴 목표 시간을 각각 설정하고 실제 진행한다. 최소 관측 및 지속 조건 이후의 빠름/느림 안내를 확인한다.
- 오인식/정정: 부정·잘못된 수치·정정은 설명됨으로 자동 승인되지 않는지 확인한다.
- 음성: 이어폰에서 안내를 듣고 음성 안내를 끄면 재생이 멈추는지 확인한다.

- 문장 중간 쉼: “음성 인식은 외부로 보내지 않고”라고 말하고 잠깐 쉰 뒤 “이 기기 안에서 실행합니다”를 이어 말한다. 앞부분만으로 완료되지 않고 이어진 내용으로 확인되는지 본다.
