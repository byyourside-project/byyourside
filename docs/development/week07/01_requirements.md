# 발표 도우미 곁 요구사항 정의서

작성일: 2026-10-12. 버전: 0.1. 대상: 개발 팀과 멘토.

## 목적과 범위

사용자가 대본과 영상을 바탕으로 발표를 연습하고, 실제 발표 중에는 목표 시간 대비 진행을 확인하도록 돕는다. 현재 PC 구현을 기능 기준으로 기록하며 최종 실행 대상은 QCS6490이다. 2026-10-12 발표 후 기록 리뷰·질문 녹음 전사·자료 원문 검색을 추가했다. 마음AI 답변 생성은 아직 연결되지 않았다.

## 기능 요구사항

| ID | 요구사항과 사용자 시나리오 | 확인 기준 | 현재 상태 |
| --- | --- | --- | --- |
| R01 | 영상·음성과 대본을 등록한다 | 지원 형식은 읽고 잘못된 형식·용량은 원인을 안내한다 | PC 구현 |
| R02 | 발화 속도·쉼을 검토한다 | 비교 가능한 구간과 근거 시각을 표시하고 근거 부족은 보류한다 | PC 구현 |
| R03 | 정면 촬영에서 카메라 방향을 추정한다 | 얼굴 없음·가림 등의 구간을 판단 불가로 구분한다 | PC 구현, 실제 정확도 미검증 |
| R04 | 피드백 구간을 다시 재생한다 | 선택한 결과의 시각으로 영상·음성을 이동한다 | PC 구현 |
| R05 | 전사를 수정하고 연습 기록을 관리한다 | 수정 반영, 저장 결과 열기, 제목 변경과 삭제가 가능하다 | PC 구현 |
| R06 | 대본과 목표 시간을 발표 중 화면에 전달한다 | 전달 후 문장 계획이 준비되며 마이크·타이머·음성은 자동 시작하지 않는다 | PC 통합 구현 |
| R07 | 실행 중인 발표 자료를 보호한다 | 발표 진행·모델 준비 중 자료 교체를 거부하고 기존 자료를 유지한다 | PC 구현 |
| R08 | 문장 진행과 계획 대비 속도를 확인한다 | 첫 문장 확인 후 표시하고 처리 중·종료 후 값의 상태를 안내한다 | PC 구현 |
| R09 | 사용자가 발표를 시작·종료하고 기록을 보관한다 | 종료 시 최종 상태를 유지하고 세션 JSON을 저장한다 | PC 구현 |
| R10 | 짧은 음성 안내를 선택한다 | 기본 꺼짐, 반복 억제, 불확실한 상태에서 안내 보류 | macOS 출력 경로, Windows·보드 미지원 |
| R11 | 발표 후 질문의 근거와 답변을 보조한다 | 발표 자료 근거를 확인하고 모르는 내용은 보류한다 | 원문 검색·질문 저장 구현, 마음AI 답변 생성 미연결 |

## 비기능 요구사항

| ID | 요구사항 | 판정 방법 |
| --- | --- | --- |
| N01 | 핵심 실행을 기기 내부에서 처리하는 구조 | 설치·모델 준비 후 외부 서비스 의존과 네트워크 흐름 점검 |
| N02 | 발표를 방해하지 않는 피드백 | 알림 횟수, 잘못된 알림, 사용자 관찰과 체감 기록 |
| N03 | 실패·자료 부족을 정상 결과와 구분 | 음성 없음, 얼굴 없음, 추론 실패, 연결 오류 시험 |
| N04 | 학습 정답과 자동 결과를 구분 | 사람 검토 상태와 학습 허용 여부 기록 |
| N05 | 실행 버전과 환경을 재현 | 코드·모델·SDK 버전, 명령, 입력 자료와 로그 보관 |
| N06 | 성능과 자원을 측정 | 지연 p50·p95, 메모리, 입력 손실, 보드 전력·발열 기록 |

지연·정확도·전력의 최종 목표 수치는 미정이다. 기존 PM 문서의 잠정 수치는 참고안이며 보드 보장값으로 쓰지 않는다.

## 환경과 제약

- 현재 검증 환경은 Windows PC다. 브라우저 화면과 Python 로컬 서버를 사용한다.
- 목표 보드 칩셋은 QCS6490이다. 특강에서는 Android·QNN/Genie·SUDA 경로와 12GB RAM을 제시한다. 실제 지급 보드의 OS 이미지·RAM과 SDK 버전은 미확인이다.
- 마음AI 모델·SDK·토크나이저·사용 조건 확인이 필요하다.
- 모델 변환은 팀 수행 범위다. 신규 양자화·양자화 보정·QAT는 수행하지 않는다.
- 클라우드는 모델 학습·평가용 GPU 사용 계획이며 지원 승인이나 상품 계약 완료를 뜻하지 않는다.
- 상대 속도를 발표의 절대적인 품질 점수로, 카메라 방향을 실제 청중과의 눈맞춤으로 표현하지 않는다.
