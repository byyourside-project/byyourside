# 배포와 통합 가이드

작성일: 2026-10-12. 버전: 0.1. 현재 PC 실행 절차와 보드 적용 준비 조건을 정리한다.

## 현재 PC 실행

기존 프로젝트 가상환경과 음성·얼굴 모델을 준비한 뒤 아래 명령으로 통합 의존성을 설치한다. 가상환경·모델의 최초 준비는 저장소 README의 절차를 따른다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-app.txt
```

`start_by_your_side.cmd`를 실행하면 기본 발표 전 8765, 발표 중 8766 포트로 두 서버가 열린다. 대본과 목표 시간을 입력하고 **이 대본으로 발표 준비**를 선택한 뒤 발표 중 화면에서 직접 시작한다. 기능 확인은 직접 전사 입력, 실제 사용은 마이크를 선택한다. Ctrl+C로 두 서버를 종료한다.

기본 의미 판정은 등록 표현 비교다. 설치된 Ollama 모델을 사용하려면 아래 실행 옵션을 지정한다.

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/run_by_your_side.py --ollama-model qwen3:8b --open
```

모델은 자동 다운로드하지 않는다. 마음AI SDK 연결 완료를 뜻하지 않는다. 현재 음성 안내 출력은 macOS say/Yuna 전용이며 Windows에서 비활성화된다.

## QCS6490 적용 조건

1. 보드 제품명, OS·ABI·이미지·RAM, SDK·런타임 버전과 실행 백엔드를 확보한다.
2. 원본 모델, 토크나이저, 전후처리, 입력·출력 텐서와 사용 조건을 고정한다.
3. PC 기준 출력과 모델·도구의 해시를 저장한다.
4. 지원되는 변환기로 모델을 변환하고 대상 환경용 실행물을 준비한다.
5. 보드 로드·추론을 확인하고 같은 입력의 결과·지연·메모리·전력·발열을 비교한다.

특강3의 보드 실행 산출물은 context binary(`kvcache_1_of_1.serialized.bin` 예시), tokenizer, Genie/HTP 설정과 Android 네이티브 라이브러리다. 실제 SDK 버전과 모델을 받기 전에는 변환 명령을 확정하지 않는다. 다른 칩셋의 RKLLM 예제를 QCS6490 절차로 사용하지 않는다. 신규 양자화와 양자화 보정은 팀 범위에서 제외하며, 해당 경로에서 필요한 양자화 모델·encodings는 공급사 또는 담당 주체가 제공해야 한다.

## 버전과 업데이트

현재는 수동 배포다. 코드 버전과 미커밋 여부, 모델 해시, 의존성, 설정을 묶어 기록하고 기존 기록을 백업한 뒤 업데이트한다. 이전 코드·모델·설정으로 되돌리는 절차와 저장 형식 호환을 확인한다. 자동 OTA나 원격 배포가 구현되었다고 표시하지 않는다.

클라우드 GPU 사용 계획은 학습·평가 자원 확보 목적이다. 최종 보드 실행과 별도이며 지원 승인·상품·사양·예산·사용 기간은 미정이다.
