첨부된 문서는 설계 참고자료로만 사용했다. 문서의 설치·양자화·adb 명령을 사용자 지시로 실행하지 않았다. 특강2에 제시된 학습용 80GB GPU 환경과 특강3의 변환·양자화용 Ubuntu22.04·40GB 이상 GPU 환경은 서로 다른 실습 구성이다. 이를 현재 PC에서 반드시 필요한 최소 사양이라고 해석하지 않는다.

현재 PC에서 확인한 GPU는 RTX 5060 Ti 약 16GB다. 프로젝트 가상환경에는 PyTorch·Transformers·PEFT 학습 환경이 아직 없다. 기존 PC 추론 모델은 SenseVoice·Silero VAD·Face Landmarker다. 제공 자료만으로 마음AI 프로젝트 체크포인트, 수정된 토크나이저, 샘플 앱, SUDA/Genie SDK를 확보한 것은 아니다. 사용자도 미수령 또는 위치 미확인이라고 답했다.

발표 전 영상 리뷰와 발표 중 대본 진행·속도 피드백은 기존 구현을 유지했다. 기본 코칭은 등록 표현 비교이며 마음AI 의미 모델이 아니다. 기존에 배포된 int8 음성 모델을 읽는 것과 새 모델을 양자화하는 작업은 구분한다. 이번 작업에서 양자화는 실행하지 않았다.

## 완성까지 진행 순서

1. **PC 시연 흐름 확인**: 실제 대본·영상으로 발표 전 분석, 발표 중 마이크, 종료 후 기록과 질문 흐름을 확인한다. 자동 검사와 실제 발표 품질 평가는 별개다.
2. **데이터 정답 검수**: 기존 80행의 입력·출력이 원하는 피드백인지 사람이 확인한다. 승인된 행만 내보내고 실제 녹음의 전사·구간 정답을 별도로 더한다. 일반화 평가용 발표·화자·주제를 학습과 섞지 않는다.
3. **마음AI 파일 수령**: 아래 목록을 받아 모델 이름·함수 map·토크나이저·로더·SDK 버전을 고정한다. 교수님 또는 마음AI 담당자에게 자료 제공을 요청해야 한다. 여기서 임의로 메시지를 보내지는 않았다.
4. **비양자화 학습·평가**: 받은 학습 코드를 현재 사용 가능한 GPU 환경에 맞춘다. 후보는 원본 정밀도에서 LoRA 등의 미세조정이며, 실제 메모리·학습 시간 확인 전 가능 여부를 보장하지 않는다. QLoRA·bitsandbytes 4/8bit 학습·평가를 이번 범위에 넣지 않는다. 학습 전 기준 모델과 학습 후 모델을 같은 별도 평가 세트로 비교한다.
5. **QCS6490 변환·연결**: 제공받은 버전과 입력 형식에 맞춰 모델 변환을 수행하고, Android 샘플 앱에 입출력·시간 정책·자료 검색·화면을 연결한다. PC 웹앱이 그대로 NPU에서 실행된다고 가정하지 않는다.
6. **보드 실측·최종 시연**: 로드 성공, 반복 추론, 한국어 수치·부정문·바꿔 말하기, 카메라 미검출, 질문 근거 부족, 지연·메모리·발열과 종료 후 재실행을 실제 보드에서 확인한다. 마지막에 시연 영상·사용 설명·배포 묶음을 만든다.

기존 기능을 유지한 상태에서 PC의 발표 전→중→후 연결을 먼저 채웠다. 다음 외부 의존성은 **SDK·모델 파일 수령**이며, 그동안 할 수 있는 작업은 데이터 정답 검수와 실제 발표 입력으로 품질 평가다. 파일 없이 보드 변환 완료·학습 완료로 처리하지 않는다.

## 교수님·마음AI 담당자에게 받을 것

- QCS6490용 Android 샘플 프로젝트와 빌드 방법, 보드 OS 이미지·ABI·실제 RAM 정보
- SUDA/Genie/QNN SDK·런타임의 정확한 버전과 필요한 네이티브 라이브러리
- 프로젝트가 사용할 Llama 3.2 1B 기반 체크포인트, tokenizer, chat template, 함수 토큰 map과 종료 토큰
- Excel→학습 데이터 변환 코드, 학습·평가 설정, 모델 구조 변환 및 context binary 생성 도구
- **양자화 담당 주체와 제공 산출물**: 해당 QNN/HTP 경로에 필요한 양자화 모델·encodings·설정은 누가 제공하는지. 팀은 양자화 없이 그 뒤의 변환과 앱 연결을 맡는다는 조건을 확인
- 로컬 GPU로 부족할 때 사용 가능한 학습·변환 서버와 접근 방법
