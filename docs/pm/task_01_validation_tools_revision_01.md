# 실사용 평가 도구 Revision 01 — 판정 신뢰성 보완

`docs/reports/task_01_validation_tools_pm_review.md`와 `logs/pm_review_validation_20260928/probes.json`을 먼저 읽는다. Revision 06 STT 구현 승인은 유지한다. 모델/추론 구조를 다시 만들지 말고 평가 도구·테스트·안내서만 수정한다.

## 수정 범위

1. **CER coverage와 정답 입력**: P01~P30 고유 ID coverage를 30문장 gate 기준으로 고정한다. 1개/29개/중복 ID/잘못된 manifest는 전체 PASS가 될 수 없다. 부분 manifest 처리 방식(완전 목록 또는 기본값에 수정 병합)을 명시하고 예시 JSON을 제공한다. 명시한 파일이 없거나 형식/정답이 잘못되면 조용히 기본값으로 대체하지 않는다. 정답/manifest 해시와 적용값을 저장한다.
2. **상태·집계 분리**: 파일 부재, 실행 오류, 부분 측정, 실제 목표 미달을 구분한다. Direct 전용에서 VAD CER는 null/NOT_RUN으로 두고 가상의 100%를 생성하지 않는다. 경로별 성공/실패 수와 CER 모집단을 명시한다. Direct 성공+VAD 실패도 일관되게 집계한다. 판단은 반올림 전 수치로 하고 표시에만 반올림한다.
3. **실패 증거 보존**: 모델 시작·warm-up·마이크 실행·파일 처리 예외도 결과 JSON에 run_id/단계/예외/가용 지표를 남기고 finally close한다. NOT_RUN/PARTIAL/ERROR/FAIL의 구조화 상태와 사람이 읽는 설명이 충돌하지 않게 한다. CLI exit code 정책도 기록한다.
4. **마이크 평가**: 누락 queue_wait_ms를 0으로 보정하지 않는다. 비수치와 부족한 표본을 검증한다. 분별 queue 분포 및 변화와 발화 분포를 보고하고 첫값-끝값 차이만으로 안정성을 단정하지 않는다. 60초 발화+540초 무음을 10분 연속 발표 PASS로 부르지 않는다. 현재 최소 발화 기준은 입력 존재 확인용으로만 사용한다. 실제 발표 coverage 적합성은 PM 검토 대상으로 PARTIAL을 유지하고 자원/지연 지표별 판정과 분리한다. 분 bin은 끝의 부분 구간도 포함하며 실제 캡처 길이와 허용 오차를 명시한다. 사람 기준 latency는 annotation 없으면 여전히 PARTIAL이다.
5. **안내서**: 불완전한 pfctl 절차와 무조건 `pfctl -d` 복구 안내를 제거한다. 다른 활성 네트워크 경로 확인 및 원상 복구 안내를 제공하되 실제 시스템을 임의 변경하지 않는다. offline 실행 성공을 송신 시도 0의 증거로 표현하지 않는다. manifest 예시, 예상 준비 시간, 장치 선택·음성 앞뒤 여유·5초 자동 절단 주의, downmix 설명을 보완한다. CER 경로 차이를 경계 손실 원인으로 단정하지 않는다.
6. **재현 메타데이터**: 사용한 config(ITN 포함), 모델 식별/해시 또는 기존 manifest 연결, 입력/정답 해시, 커밋+dirty 상태, 마이크 장치 정보를 결과에 기록한다. 실행별 고유 경로를 유지하고 명시적 output 경로의 기존 파일 덮어쓰기 정책을 안전하게 정의한다.

## 필요한 작은 회귀 테스트

실제 모델·마이크 없이 fake 반환값과 예외를 주입하여 신규 판정 로직을 테스트한다. PM 진단은 STT 성능 증거가 아닌 평가 코드의 논리 재현이다.

- 0/1/29/30 고유 문항, 중복 ID, 잘못된/미존재 manifest.
- 전부 ERROR, Direct만 성공하고 VAD 실패, direct 모드의 미측정 VAD 지표.
- queue 필드 누락/비수치, 중간에 큐가 증가했다가 마지막에 해소된 경우, 성긴 발화, 전 구간 분산 발화, 부분 마지막 minute.
- 초기화/warm-up/run_mic 실패에도 JSON 보존 및 close 호출.
- 성공/오류/미실행 상태가 설명과 일치하고 기존 출력이 보존되는지.

먼저 새 테스트를 실행한다. 모델 코드가 변경되지 않았다면 같은 51개 모델 회귀 전체를 반복할 필요는 없다. `--help`는 인터페이스 확인으로만 보고하고 판정 테스트로 세지 않는다. 실제 마이크 10분 시험과 시스템 네트워크 변경은 수행하지 않는다.

결과를 `docs/reports/task_01_validation_tools_revision_01_report.md`에 명령·실제 test ID·exit code·고유 로그와 함께 기록하고 PM 검수를 기다린다. 사용자 음성이 없으면 실사용 성능 NOT_RUN을 유지한다. Task 02는 시작하지 않는다.
