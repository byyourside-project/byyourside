# Task 01 Revision 03 — 전체 구간 보존과 검수 근거 보완

먼저 docs/reports/task_01_revision_02_pm_review.md를 읽는다. Task 02는 시작하지 않는다. 이전 코드·로그의 사용자 변경은 보존한다.

## 우선 작업

1. F1: hard cut 뒤 VAD 재초기화로 166ms가 사라지는 재현을 테스트에 추가한다. 전체 발화의 모든 구간을 검사한다. VAD 상태를 유지하면서 ASR 분할을 별도 관리하거나 동등한 보존 구조를 구현한다. 경계마다 재탐지로 음성이 빠지면 안 된다. 작은 continuation은 다음 입력과 합치는 방법을 검토하되 최대 지연도 함께 측정한다.
2. F2: STT가 2초 이상 대기하는 재현을 추가하고 timeout·cancel 이후 worker/로그 수명 정책을 수정한다. Python thread를 강제 종료할 수 있다고 가정하지 않는다. 취소 불가능한 native 연산의 timeout은 프로세스 격리 또는 명시적인 완료 대기 등 검증 가능한 정책으로 처리한다. 반환 뒤 살아 있는 worker, 닫힌 logger 접근, 재실행 시 이전 worker 간섭이 없도록 한다.
3. F3: 결과 구간에 실제 queue_wait_ms를 보존하고 누락된 값은 0으로 간주하지 않는다. 증가하는 밀림, 필드 누락, 정상 안정 상태 각각의 판정을 검증한다.
4. F4: 60초 smoke test와 600초 안정성 gate를 분리한다. 60초 실행은 10분 기준을 통과할 수 없게 한다. 기존 60초 로그는 보존하고 보고서의 판정을 정정한다.

## 결정적 회귀검증

- 기존 forced-cutoff fixture: 첫 두 구간뿐 아니라 모든 구간 연결을 확인하고 [70656,73312) 손실이 없어야 한다. frame padding과 의도적인 VAD 무음 제거는 별도 표시한다.
- 연속 음성의 3회 이상 hard cut, 여러 절단 위치에서 구간 길이·sample coverage·비의도 중복을 검증한다. 정답 파형은 현재 출력에서 생성하지 않는다.
- STT/VAD 예외, 장시간 추론 timeout, 마이크 시작 실패, 사용자 중단에서 worker와 파일 핸들을 확인한다. 외부 시간제한이 있는 자식 프로세스로 hang 테스트를 격리하고 깨끗이 종료한다.
- 큐 지연 증가 입력은 안정성 FAIL, 지연 필드 누락은 NOT_RUN/검증 실패여야 한다.
- 60초 기록은 600초 요구사항에 PARTIAL/NOT_RUN이어야 한다.

짧은 회귀검증을 모두 통과하기 전 10분 마이크 재실행을 하지 않는다. 그 후 실제 사용 환경에서 가능한 경우에만 600초 시험을 수행한다. 실제 발화 부재·마이크 접근 불가는 NOT_RUN으로 둔다. 30문장 CER, OS egress, 실제 발화 종료 annotation 미확보 상태는 계속 명시한다.
