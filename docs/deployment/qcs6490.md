# QCS6490·마음AI 적용 범위와 인계 규격

발표 전 기능은 현재 PC에서 대본·영상을 받아 음성 인식, 상대 말하기 속도, 쉼, 카메라 방향 추정, 구간 재생과 기록 저장까지 수행한다. 목표 하드웨어는 **QCS6490**, 마음AI 사용 계획은 유지한다. **보드용 모델 변환은 팀 범위, 양자화는 팀 작업 범위 밖**이다. PC 동작 확인을 보드 적용 완료로 표시하지 않는다.

## 확정된 사항과 미정 사항

| 항목 | 상태 |
| --- | --- |
| 목표 칩셋 | QCS6490 |
| 마음AI 연동 의도 | 유지. 근거를 설명하는 한국어 코칭 문장 생성에 연결할 경계 준비 |
| PC 추론 | 기존 Silero VAD·SenseVoice와 MediaPipe Face Landmarker CPU |
| 보드 OS·이미지 버전·실제 RAM | 미정 |
| 마음AI SDK 파일·버전·API·배포 조건 | 미정 |
| 마음AI 제공 LLM·토크나이저·프롬프트 형식 | 미정 |
| QNN/QAIRT 버전·지원 대상·컴파일 호스트·백엔드 | 미정 |
| 보드 실행·성능·발열·메모리 검증 | 미실시 |
| 보드 모델 변환 | SDK·원본 모델·타깃 확인 후 수행, 아직 미실시 |
| 새 양자화 | 수행하지 않음 |

2026-10-05 개발 환경 확인에서는 `adb`를 찾지 못했고 `QNN_SDK_ROOT`, `QAIRT_SDK_ROOT`, `ANDROID_HOME`도 설정되지 않았다. 설치 여부 전체를 단정하는 검사는 아니지만, 현 작업 환경에 보드 변환·실행 경로가 구성되어 있다고 볼 근거가 없다.

제공 강의 중 Android/JNI/QNN/Genie 자료는 Android를 택할 경우의 참고 경로다. 통합 강의의 Orange Pi/RK3588·RKLLM 예제는 다른 칩셋용이므로 QCS6490에 적용하지 않는다. 강의의 예시 버전이나 메모리 수치를 실제 지급 보드 사양으로 확정하지 않는다.

## 현재 만들어진 마음AI 입력

`src/review_handoff.py`의 `build_handoff(report)`는 측정 근거와 프롬프트를 JSON으로 만든다. SDK 호출·모델 추론·네트워크 전송은 하지 않는다. 서버에서 보고서와 함께 `coaching_input.json`으로 저장한다.

| 필드 | 의미 |
| --- | --- |
| `schema_version` | 인계 데이터 버전, 현재 1 |
| `task` | `pre_presentation_review` |
| `integration_status` | 항상 `sdk_not_configured`; 실행하지 않은 추론을 성공으로 표시하지 않음 |
| `evidence.pace` | 비교 기준, 확인 가능한 속도·쉼 구간, 제외 구간 수, 경험 기준과 한계 |
| `evidence.gaze` | 분석 가능 비율, 정면 추정 비율, 다시 볼 구간, 판단 보류 이유와 한계 |
| `evidence.schedule` | 목표와 실제 총시간 차이. 전달력·순간 속도와 구별 |
| `prompt.system` | 측정값 밖의 수치·점수·원인을 만들지 않는 한국어 코칭 지시 |
| `prompt.user` | `task`와 `evidence`만 담은 JSON 문자열 |
| `training_eligible` | `false`; 검토되지 않은 자동 분석을 학습 정답으로 취급하지 않음 |
| `quantization_performed` | `false`; 기존 공개 모델의 정밀도와 이번 작업 여부를 구분 |

대본 전문, 전사 전문, 제목, 원본 영상·음성, 얼굴 좌표, 파일 경로, 내부 재생 URL을 입력에 넣지 않는다. 코칭 문장에는 필요한 시각과 측정값만 제공한다. 사용자 자료에서 유래한 텍스트를 시스템 지시로 승격하지 않는다. 현재 인계 규격은 구체적인 대본 내용을 요약하는 목적이 아니라 속도·시선 검토를 설명하는 목적이다.

SDK 연결 후에도 `unavailable`, `insufficient_evidence`, `unconfirmed`, `no_speech`를 문장 생성기가 좋은 평가로 바꾸면 안 된다. 전체 시간 안에 끝났다는 사실은 말을 적절하게 했다는 판정이 아니다. 실제 청중과 눈을 맞췄는지는 측정하지 않는다. 모델 응답을 적용하기 전에는 없는 시간·수치가 생기지 않는지 검사하고, 실패할 때 현재의 측정 기반 문구를 유지한다.

## 보드에서도 유지할 경계

화면은 보고서 JSON과 구간 시각을 사용한다. 미디어 읽기·음성 추론·얼굴 추론·코칭 생성은 각 실행 환경의 어댑터 뒤에 둔다. 따라서 Android를 택하면 Kotlin UI 또는 WebView와 C++/JNI 추론 사이에서 같은 측정 규격을 유지할 수 있고, Linux를 택하면 해당 OS용 실행 계층으로 대체할 수 있다. 이것은 설계 경계이며 Android·Linux 중 실제 사용 OS가 결정됐다는 뜻이 아니다.

Google은 Android Face Landmarker에서 `.task` 모델을 로드하고 이미지·영상 모드로 사용하는 방법을 제공한다. Android 선택 시 현재 모델 묶음과 얼굴 후처리 규칙을 옮기는 경로를 먼저 검토할 수 있다. **Python 패키지를 보드에 그대로 설치하거나 `.task`가 곧 QNN 실행 바이너리라고 가정하지 않는다.** 이 경로가 QCS6490 NPU를 사용한다거나 같은 속도를 낸다는 보장은 없다. [Google Android Face Landmarker 안내](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker/android)

홍채 특징점 모델 자체는 사람이 실제로 보는 지점을 추론하지 않는다. 현재 정면 방향 규칙은 별도의 제품 경험 기준이며, 발표 영상으로 오탐과 미탐을 확인해야 한다. 정면, 대본 보기, 옆 방향, 눈 감김, 가림 구간에 대한 사람 검토가 필요하다. [Google MediaPipe Iris 설명](https://chuoling.github.io/mediapipe/solutions/iris.html)

## 변환 작업의 입력·출력과 진행 조건

1. **실행 대상을 먼저 고정한다.** 보드 OS/ABI, SDK 버전, CPU/GPU/HTP 중 사용할 백엔드, 지원 연산, 입력 형상과 정밀도를 기록한다. 최신 Snapdragon 문서의 기능을 QCS6490 지원으로 추정하지 않는다.
2. **원본 모델과 전후처리를 확보한다.** 모델 가중치, 그래프, 토크나이저, 음성 특징 추출, 얼굴 ROI·랜드마크 처리, 입력·출력 텐서 이름/형상/자료형, 라이선스와 해시를 한 묶음으로 고정한다. LLM은 마음AI가 지정한 원본 또는 제공 실행물을 기준으로 한다.
3. **PC 기준 출력을 저장한다.** 같은 입력에 대한 전사·얼굴 좌표 또는 측정값·LLM 토큰 출력을 기록한다. 변환 후 비교용 자료이며 양자화 보정 데이터셋이 아니다. 실제 얼굴·음성 기준 자료는 외부로 보내지 않는다.
4. **확인된 변환기만 실행한다.** SDK가 지원하는 원본 형식에서 타깃 형식으로 그래프·패키지를 변환한다. 버전에 따라 중간 산출물이 달라지므로 확인 전 `.cpp/.bin`, `.dlc`, `.so` 또는 컨텍스트 바이너리 중 하나를 고정하거나 추정 명령을 실행하지 않는다. Qualcomm은 변환 후 대상 OS와 아키텍처에 맞춘 별도 빌드 단계를 설명한다. [Qualcomm 대상 OS용 모델 빌드 안내](https://docs.qualcomm.com/nav/home/qnn_tutorial_windows_host_linux_target.html?product=924033590759186372)
5. **양자화 없이 가능한 경로를 확인한다.** 새 INT8/INT4 변환, 양자화 보정, QAT, AIMET·quantizer 실행은 하지 않는다. 선택 백엔드가 현재 원본 정밀도를 지원하지 않으면 자동으로 양자화하지 않고, 지원되는 다른 실행 경로나 공급사 제공 실행물을 검토한다. 기존 PC의 공개 SenseVoice INT8 모델을 사용하는 것과 팀이 새로 양자화하는 것은 다른 작업이다. CPU·GPU·HTP 지원 범위는 해당 SDK/칩셋에서 따로 확인한다. [Qualcomm CPU 백엔드 자료](https://docs.qualcomm.com/nav/home/cpu_backend.html?product=924033590759186372)
6. **변환 산출물과 검증 증거를 함께 인계한다.** 원본/산출물 해시, 도구와 OS 버전, 입력·출력 명세, 전후처리 코드, 기준 출력과 차이, 누락·미지원 연산, 실제 실행 백엔드, 메모리·시간 측정 결과를 기록한다. 보드에서 로드와 추론이 성공하고 기준 결과가 재현되어야 적용 완료로 표시한다.

현재 단계에서 PC 기능을 쓰기 위해 사용자에게 보드 설정이나 추가 촬영을 요구하지 않는다. 보드 SDK 자료가 확보되면 위 미정 항목부터 채우고 변환·실행 검증을 진행한다.
