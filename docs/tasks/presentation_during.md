# 발표 중 기능 작업 계획

작성일: 2026-10-04
현재 상태(2026-10-05): 대본 준비·시간 계획·로컬 내용 판단·진행 위치·속도 음성 안내를 구현했다. 빠름·느림 음성은 실제 발화 시각으로 계산하고 처리 지연·입력 손실·반복 낭독을 보수적으로 처리한다. 실제 사람의 장시간 발표와 이어폰·보드 통합 검증은 남아 있다. 아래 초기 계획·과거 검수 기록은 당시 상태를 보존한다.

최신 속도 안내 구현·검수: [발표 속도 음성 안내 보고서](../reports/presentation_pace_voice.md).
연속 발화의 앞 문장 처리 지연 수정·검수: [대본 확인 지연 보고서](../reports/presentation_live_latency.md). 앞 문장의 안전한 결과를 우선 반영하고, 최신 정정·처리 대기는 구분한다.

## 2026-10-05 요구사항 정정 — 아래 기존 계획보다 우선

사용자 요청의 핵심은 **대본을 넣고, 대본 대비 진행·누락·사전 계산한 속도 차이를 판단해 음성으로 안내**하는 것이다. 기존 계획에서 속도와 TTS를 확장으로 미룬 범위를 정정한다. 두 기능은 대본 진행 추적과 함께 핵심 구현 범위에 포함한다.

작업 순서: 대본 입력/시간 계획 → 대본 위치 추적 → 지나친 구간의 누락 후보 확인 → 계획 대비 속도 안내 → 음성 출력/재생 기록 → 실제 마이크와 음성 출력 통합 시험.

기존 STT·세션·타이머·의미 모델은 기반으로 재사용한다. Q&A·자동 화자 분리는 후속으로 둔다. 현재 공통 계약 v1은 대본/속도/TTS를 지원하지 않으며 신규 계약 구현 때 별도로 갱신한다. 아래 기존 완료 항목은 제품 전체 완료를 뜻하지 않는다.

새 실제 시험 기록의 실패 분석, 상세 완료 기준: [발표 중 요구사항 재검토](../reports/presentation_requirements_recheck.md).

## 목적과 현재 상태

현재 슬라이드와 발화를 연결하고 시간·내용 진행 상태를 표시한다. 필요한 순간에 짧은 코칭을 제공하며, 모든 판단의 근거를 발표 후 분석에 남긴다.

기존 음성 입력·VAD·한국어 STT에 세션 상태, 슬라이드 타이머, 발화 이벤트 연결, 문맥 유지, 핵심 항목 확인, 알림 정책, 로컬 진행 화면과 종료 기록 저장을 연결했다. 기본 내용 판단은 핵심 문장·허용 표현을 확인하는 보수적 기준선이며, 일반 의미 판단용 로컬 모델 어댑터 인터페이스를 제공한다. Task 01 전체 성능은 PARTIAL이며 실제 발표 검증이 남아 있다.

실행 안내: `docs/user/presentation_during_guide.md`. 공통 자료·이벤트 계약: `docs/tasks/presentation_contract.md`.

후속 진행: 설치된 Ollama 로컬 모델을 직접 연결하고 정답 전사 개발 평가 20개를 추가했다. 기본 문장 매칭 모드와 선택적 의미 모델 모드를 구분하며, 모델 정확도와 요청 지연을 따로 측정한다. 독립 발표 자료·실제 음성의 품질 검증은 남아 있다.

## 1차 구현 범위

| 작업 | 상세 내용 | 완료 기준 |
|---|---|---|
| 발표 진행 제어 | 시작·종료, 현재 슬라이드와 수동 이전·다음 전환 | 전환 시각과 대상 슬라이드가 기록되고 세션 종료 상태가 저장된다. |
| 타이머 | 전체·슬라이드 경과 시간과 남은 시간 표시 | monotonic clock으로 계산하고 슬라이드 전환 시 해당 타이머를 갱신한다. |
| STT 이벤트 연결 | 확정 발화를 세션 상태와 화면에 전달 | 세션·구간 ID와 음성 시간 범위를 보존하고 누락·오류 상태를 표시한다. |
| 발화 문맥 유지 | 최근 발화를 유지하고 강제 분할된 문장 조각을 연결해 판단 | 미완성 발화 하나만으로 의미를 단정하지 않고 원래 구간의 근거를 유지한다. |
| 핵심 항목 상태 | 미확인·설명됨·판단불가 상태 관리 | 바꿔 말하기와 불확실한 전사를 구분하며 판단 근거 구간을 저장한다. |
| 시간 알림 | 전체 잔여 시간과 슬라이드 목표 시간 초과를 규칙으로 판단 | LLM 없이 계산하고 같은 조건의 알림이 반복되지 않는다. |
| 내용 누락 코칭 | 슬라이드 전환·발표 종료 시 필수 항목 누락 후보 평가 | 아직 설명 중인 내용을 즉시 누락으로 경고하지 않는다. |
| 알림 정책 | 중복 억제, 간격, 우선순위, 만료 시간, 무알림·판단 유보 처리 | 정상 진행에서는 개입을 억제하고 이전 슬라이드 결과를 현재 화면에 적용하지 않는다. |
| 진행 화면 | 현재 슬라이드, 타이머, 항목 상태, 짧은 알림 표시 | 사용자가 발표하면서 필요한 정보를 읽을 수 있다. |

## 후속 구현 범위

- 수치·용어 불일치 코칭: 준비한 기준과 발화를 비교하고 근거가 부족하면 판단을 유보한다.
- 속도 안내: 전사 기반의 근사 속도와 리허설 기준을 비교한다. 정확한 음절 속도나 습관어 횟수로 표시하지 않는다.
- 이어폰 TTS: 중요한 알림만 별도 큐에서 재생하고 화면 갱신을 막지 않는다.
- Q&A: 질문자/발표자 모드를 수동 전환하고 질문·답변을 구분해 기록한다.
- 자동 슬라이드 전환 연동과 자동 화자 분리: 수동 흐름이 검증된 뒤 별도 평가한다.

## 공통 데이터와 다른 단계에 전달할 내용

- 발표 전 입력: 자료 스냅샷, 슬라이드 순서, 핵심 항목, 목표 시간, session_id.
- 발화 이벤트: segment_id, 음성 시작·종료 시간, 전사, 오류·손실 상태.
- 진행 이벤트: 슬라이드 전환, 세션 시작·종료, 전체·슬라이드 경과 시간.
- 판단 이벤트: 대상 항목, 상태 변화, 근거 구간 ID, 판단 사유, 코칭 후보.
- 알림 이벤트: 화면에 실제 표시한 메시지, 표시 시각, 대상 슬라이드·항목, 억제 사유.

발화가 슬라이드 전환 경계에 걸릴 때의 연결 규칙을 정한다. 최소한 음성 시간 범위와 전환 시각을 보존하고, STT 결과 도착 시점의 슬라이드에 무조건 연결하지 않는다. 지연된 코칭 결과에는 세션·슬라이드 상태 버전을 검증한다.

## 권장 작업 순서

1. 정답 전사와 슬라이드만 사용해 내용 판단 기준선 평가.
2. 세션 상태·수동 슬라이드 전환·타이머 구현.
3. 기존 STT 결과를 전달하는 이벤트 인터페이스 구현.
4. 발화 문맥과 핵심 항목 상태 관리 구현.
5. 시간 알림·내용 코칭·공통 알림 정책 연결.
6. 진행 화면과 발표 후 기록 연결.
7. 실제 음성 통합 평가 후 TTS·Q&A 확장.

## 검증 항목과 잠정 목표

- 정상 설명, 바꿔 말하기, 미언급, 실제 누락, 부정, 숫자 오류, 불확실 사례를 구분한다.
- 구조적으로 유효한 모델 출력과 의미 판단 정확도를 별도로 평가한다.
- 강제 분할된 발화, 전환 경계 발화, 지연된 모델 응답, 큐 과부하를 시험한다.
- 알림이 필요 없는 구간의 오경보와 중복 알림을 측정한다.
- 잠정 목표: 발화 종료부터 화면 피드백 p95 3초, 타이머 조건 성립부터 화면 표시 0.3초. 기존 설계 제안값이며 실측을 통해 확정한다.
- STT 계산시간만으로 전체 피드백 지연을 대신하지 않는다. 연속 발화의 구간 수집 시간도 따로 보고한다.
- 사용자 준비에 맞춰 실제 30문장 CER·최신 버전 600초 발표·사람 발화 종료 라벨·오프라인 실행 증거를 확보한다.

## 범위에서 제외

표정·시선 분석, 근거 없는 종합 점수, 자동 개인화 학습은 초기 범위에 포함하지 않는다. 모델 출력은 허용된 액션과 파라미터를 검증해서 사용한다.

## 이번 후속 작업 결과

로컬 Ollama 의미 모델 연결과 정답 전사 평가 CLI를 추가했다. 최종 개발 사례 19/20, 구조 유효성 100%, 단일 항목 요청 p95 1.12초다. 다중 항목에서는 기본 2초 타임아웃이 재현됐다. 실제 음성 통합과 독립 평가가 다음 우선 작업이며 TTS·Q&A는 그 이후 진행한다. 상세 내용은 docs/reports/presentation_semantic_implementation_report.md에 기록한다.

## 검수 및 다중 항목 평가 보완

정정 발화의 판단 실패 시 과거 설명됨을 유지하던 경로를 수정했다. 다중 항목 정답 평가와 실패 요청 시간 기록을 추가했다. 최신 개발 결과는 단일 20/20, 다중 8/8이며 다중 p95 3.10초로 실시간 2초 목표는 미충족이다. 성능 개선 완료로 표시하지 않는다. 상세: docs/reports/presentation_coaching_review.md.

## 2026-10-05 대본 핵심 흐름 구현
